## 1. 已经确定的目标

用户已确认：**3 Alice training seeds × 3 maps × 50 个严格配对事件 = 450 个事件**；从开始覆盖全部 8 类意图。

研究问题：Alice 通过训练提高能力后，Bob 使用过去的相处记录，是否更容易误解 Alice 当前动作的目标？更新相处记录后，理解和配合是否改善？

Alice 使用可训练 MLP，Bob 使用 `Qwen/Qwen3.5-9B` 预测意图及目标设施，固定控制器将预测转换为配合动作。印象是公开可见历史的 JSON 文本上下文，不提供 Alice 的身份阶段、网络参数或真实目标。

主要报告两个指标：**Bob 意图准确率、团队得分**。设施准确率、弃答、类别混淆和堵塞用于解释问题。M17 是先导证据，M18 的训练、样本和结果单独保存。

## 2. 三项评估，分别回答什么

| 部分 | 每个训练 seed×地图的样本 | 作用 |
|---|---:|---|
| A：严格配对动作解释 | 50 个，共 450 个 | 同一公开局面、相同第一步动作，成长前后意图不同；在成长后 Alice 上比较旧/新/无印象 |
| A-score：关键局面续局 | 复用 A 的 450 个局面 | 从观察结束后继续 200 步，预测仅注入一次，检查是否影响得分 |
| D：一般可见决策诊断 | 额外 50 个，共 450 个 | 不要求成长前后意图不同或第一步相同；了解全意图中的容易、困难和缺失类别 |
| B：完整合作局 | 每组 16 个起点，9 组共 144 个起点 | 从随机合法起点合作 700 步，每种条件分别跑；检验自然合作影响 |

450 是 A 的事件数，既不是 450 次训练，也不是 B 的游戏局数。D/B 是建议增加的评估量，需本轮审核。A-score 仍是受控续局，不能代替 B。

建议顺序：本地代码与地图验收 → Alice 训练和能力验收 → 历史/候选可行性检查 → 少量开发 API → 冻结提示词与数据 → A/D/A-score → B。后续阶段以数据完整性和程序验收为条件，不以“结果支持动机”为进入条件。

### 3.2 公共设置

- 环境沿用项目 Overcooked-AI；Python 3.11，Conda `agentresume`，设置 `PYTHONNOUSERSITE=1` 和 `PYTHONPATH=src`。
- 训练和完整局 700 tick，汤的稀疏奖励 20 分/份。主得分同时写原始分数和份数，避免混淆。
- 开局空手、空锅；从全部可通行格均匀抽取两个不同位置，朝向固定向右。不人为把 Bob 放在 Alice 身旁。
- Bob 的动态观察为自身中心 3×3 方形视野（半径 1，沿用项目几何判断），知道静态地图；不补写视野外动态状态。正式说明这不是带视线遮挡的视觉模型。
- Alice 沿用全局结构化输入；Bob 为局部观察，两者信息不对称需在论文中明示。
- GPU 可用则使用 CUDA；训练前只核对解释器、PyTorch 和实际设备并落盘，不依据旧文档假定 GPU 一定可用。

## 4. Alice：让全部意图有机会出现

### 4.1 必须改变的角色安排【审核项 1】

旧版示范中 Alice 长期负责 cook，伙伴负责 serve，可能导致取盘、盛汤、送餐示范不足。建议改为**交替角色示范**：每交付一份汤交换做饭/送餐分工，先完成手中物品再换任务。示范 Alice 保持保守策略，固定伙伴保持原有规则。

PPO 阶段 Alice 自由选择 8 类合法意图，角色只影响规则伙伴的任务与等待位置，不给 Alice 增加意图标签输入。执行器角色等待提示应与角色安排同步，不保留写死的 `role_hint="cook"`。能力验收使用同一个固定伙伴，Bob 印象条件不参与训练和 checkpoint 选择。

这会改变 M17 的训练分布，成长是否成立需要重新检验；不能预设一定提高，也不以 PRE→FETCH 作为成功标准。

### 4.2 提议训练参数

| 项目 | 配置 |
|---|---|
| 网络随机 seed | 1801、1802、1803；三张地图各独立训练一次，共 9 条成长链 |
| 网络 | 182 → 128 Tanh → 128 Tanh → 8；3 口锅、11×7 对应 182 维 |
| BC 示范 | 每组 24 个完整 episode，只取新宏观任务开始时样本 |
| BC | 100 epochs，batch 256，Adam lr=0.003，weight_decay=0.0001，训练集逆频率类别权重交叉熵；最终 epoch 保存 pre |
| PPO | 从对应 pre 继续；50 updates，每次 8 episodes，共 400 局/成长链 |
| PPO 参数 | lr=0.0003，采样 temperature=5，entropy=0.08，gamma=0.995，GAE lambda=0.95，clip=0.2，value coef=0.5，4 epochs/update，batch 256 |
| 奖励 | 每交付一份汤 +1 供训练使用，对应游戏 +20；不引入意图、印象相关奖励 |
| 选 post | 每 5 updates 在固定 16 起点验证；平均交付量最高，平局取较早 checkpoint；pre 纳入候选 |
| 独立能力测试 | 32 起点，同起点比较 pre/post；确定 checkpoint 后才读取测试结果 |
| 成长验收 | 每组平均提升至少 1 份汤，且至少 17/32 起点提升；全部 9 组报告 |
| 正式推理 | Alice 使用合法意图掩码后 argmax，最大宏观任务时长 50 tick；所有条件相同 |

以上训练参数多数沿用现有 M16 脚本；交替角色、32 起点和验收阈值为 M18 新建议。若某组成长未通过，记录为操纵失败，先汇报，再决定修订训练；不能替换 seed 或只发表成功组。

BC 开始前逐类报告示范样本数；任一类为零时先报告覆盖问题并修订示范方案，不把随机初始化的缺类输出当作“已经学会全部任务”。有样本也不等于每类已学会，另报各类模仿正确率和闭环出现频率。

### 4.3 seed 与来源隔离

组合编号 `g=3×map_index+seed_index`，从 0 到 8；该组的 episode seed 基数 `b=100000×(g+1)`。

| 用途 | seed（均加 b） |
|---|---|
| 本地开发验收 | 1–16 |
| BC 示范 | 100–123 |
| checkpoint 验证 | 200–215 |
| 独立能力测试 | 300–331 |
| PPO 起点 | 1000–1399，按 update 顺序分配，每局唯一 |
| 印象来源 | 2000–2039，共 40 个 pre/post 配对起点 |
| 开发候选来源 | 3000–3019 |
| A 正式候选来源 | 4000–4099 |
| D 正式轨迹来源 | 5000–5039 |
| B 正式起点 | 6000–6015 |

所有起点使用同一实现 `random.Random(5000+episode_seed)` 从排序后的可通行格取样。不同 seed 仍可能抽中同一位置，故还须核对世界状态和观察哈希；episode seed 隔离不能替代重复检查。

## 5. Bob：看到什么、猜什么

### 5.1 8 类目标

| 标签 | 自然语言含义 | 设施类型 |
|---|---|---|
| FETCH | 去取洋葱 | 洋葱台 |
| PLACE | 将手中洋葱放入锅 | 锅 |
| COOK_START | 启动满锅烹饪 | 锅 |
| GET_DISH | 去取盘子 | 盘台 |
| PICKUP | 用盘子盛熟汤 | 锅 |
| DELIVER | 将汤送到出餐口 | 出餐口 |
| PRE | 到烹饪锅附近照看、准备或等待 | 锅 |
| HOLD | 暂缓任务或到安全位置等待/让行 | none |

允许 `unknown` 表示不能判断；它不属于 Alice 的第九类意图。设施用“锅 A”等稳定 ID，不预测精确站位。`PRE` 的目标是锅，即使执行器实际走向附近等待格；`HOLD` 目标标签为 none。真实标签以**产生被观察动作的那次宏观任务**为准，不能错取动作完成后下一任务的标签。

### 5.2 提示词与输出约定

所有条件使用完全相同的任务说明和当前事实，只替换历史。提示不透露“成长前/后”“这是歧义事件”、候选意图对或真实合法掩码；8 类定义始终相同。模型可引用地图和可见事实作推测，不能把推测声称为视野外观测。

建议固定系统提示核心如下（实现时完整文本与哈希落盘）：

> 你是 Bob。根据刚观察到的 Alice 动作、当前可见事实和提供的相处记录，推测产生这个动作的任务目标。意图含义见固定的八类定义。历史只代表过去，不能假设当前一定相同。看不清时可回答 unknown。目标设施是预测，不是已观察事实。只引用输入签发的事实编号，不补写视野外动作、目标或锅状态。只输出规定 JSON。

```json
{"intent":"FETCH","target_facility":"onion_A","confidence":0.7,"used_fact_ids":["C1","H2"]}
```

示例仅解释格式，正式提示使用占位 schema，不嵌入偏向 FETCH 的示范。模型 `Qwen/Qwen3.5-9B`，temperature=0，max_tokens=256，沿用经过开发验证的非思考接口设置。模型与实际请求参数记录；服务版本不可固定时，记录时间和返回的模型 ID。

每个输入独立请求 3 次，多数票确定意图；无多数、弃答或无效均计入准确率分母。设施仅在多数意图对应的输出中投票，无多数则 unknown。合法但猜错的回答直接保留；格式错误不通过“请再想一想”修正。传输失败最多补发 2 次，完整记录原始尝试并计入调用上限。

提示词约束和事实 ID 校验只能减少无依据陈述，不能保证模型内部完全不猜测。

## 6. 印象如何得到【审核项 2】

主条件建议保留 **旧印象、新印象、无印象**。旧/新均来自同一训练链 pre/post 的公开相处记录，来源起点配对，Bob 使用同一个无印象基础控制器。

- 每组 40 个来源起点，pre/post 各跑 700 tick。只保存 Bob 连续可见片段；离开视野立即结束，重新出现建立新片段。
- 每段最多 12 tick，至少两个连续可见帧。达到 12 tick 截断后不对仍连续可见的同一段反复滑窗取样。
- 每个来源 episode 每阶段最多取 2 段，按出现时间取最早合格段；只保留 pre/post 均有合格段的来源 episode，每对 episode 取相同段数。
- 每阶段最多 80 段；至少 40 段且来自至少 20 个配对 episode 才进入正式阶段。报告被排除 episode 和原因，结论限于能观察到的历史。
- 无人工意图标注，不读取隐藏完成事件。片段中的持物变化、锅况和互动只有在可见时才能记录。禁止用训练阶段、真实意图或测试答案检索。
- 每次取 top-5：公开动作种类相同 +2、移动方向相同 +4、可见手持物相同 +2，再减去 Bob 两次位置 Manhattan 距离×0.05；缺失项不加分，平局按来源 ID。
- 每段最多展示 4 帧（首两帧和末两帧，去重），时间改成片段相对时间；格式、容量与确定性截断规则一致。记录实际 token，旧/新内容长度不强行伪造相等。

其他伙伴 Charlie 印象建议先列为可选扩展。它需要额外定义伙伴训练与习惯差异，不能默认另一个训练 seed 就代表有不同习惯。本轮主实验先隔离“过去/现在的相处记录”这一变化。

## 7. 如何获得 450 个配对事件【审核项 3】

### 7.1 使用可追溯的来源状态

每组在专用来源起点上，用 pre/post Alice 与同一基础 Bob 采集轨迹。在宏观任务边界保存完整世界快照及回放动作。对每个候选快照克隆两个世界，清空 Alice 旧任务缓存，让 pre/post 分别重新选择目标；Bob 在被观察的第一步固定 STAY。

保留条件：世界快照相同、Bob 观察相同、Alice 选择意图不同、实际完成的第一步动作相同、动作后 Bob 公开观察相同，且动作前后 Alice 都可见。比较实际位移/转向/可见互动，不能把被挡住的移动请求当成移动。

这是对真实轨迹状态的**受控重新决策**，不是声称两位 Alice 自然同时来到这里。快照需可从记录的起点和动作回放还原。与旧版纯状态枚举相比，状态来源更可追溯。

### 7.2 去重、覆盖和抽样

历史、开发、A、D、B 来源 episode 整体隔离；pre/post 对应同一个来源 seed 的轨迹视为同组。跨区完全相同的公共事件哈希剔除。近重复族定义为：地图、Alice 手持物、可见锅况、第一步动作类型/方向、Alice 和 Bob 所在 2×2 位置分区均相同；跨区同族优先保留历史，其次开发，其次正式。先生成来源分组与排除记录，再选正式样本。

公共事件哈希去掉 event ID、episode seed、绝对时间和条件名，保留公开的空间/持物/锅况/动作内容，避免仅时间编号不同就逃过重复检查。2×2 位置分区定义为 `(x//2,y//2)`。B 自然发生的相似局面不人为删除；报告其与历史/A/D 的重叠率，B 的独立性来自专用来源起点而非保证从不遇到同一厨房局面。

每个正式来源 episode 最多入选 1 个 A 事件，每个近重复族最多入选 1 个。对实际存在的 post 意图按等额分配 50 名额，稀缺类别取完后将余量按固定标签顺序轮转分配；类内使用 `18000+g` 的固定 seed 抽样。必须在 Qwen 调用前冻结事件清单及哈希。

全意图预测不保证严格配对子集 8 类齐全。报告每类候选/入选数、pre→post 转移表、涉及 HOLD 的比例及排除 HOLD 后的辅助结果。若缺少某类，不能通过人工修改 Alice 标签补齐。

不足 50 个或历史不足时报告可行性失败；不重复计数、放宽规则补满，也不更换失败 seed。D 使用独立自然轨迹中可见的真实新任务事件，按全部合格事件固定 seed 均匀抽 50 个，每 episode 最多 2 个；不按预测答案或意图配额挑选。D 反映可见决策分布，与 A 的分层歧义分布分别报告。

## 8. Bob 如何把预测用于配合

训练伙伴、历史采集 Bob、正式 Bob 是不同职责，必须分别记配置。正式所有印象条件使用相同 Bob 控制器。

基础优先级：先处理自己手中物品；空手时根据可见/有时间戳的记忆状态，依次考虑已熟汤配套取盘、启动满锅、补原料、烹饪期间取盘、最后安全等待。只用 Bob 可获得的信息，不能调用读取全局锅态的 Alice 合法掩码或规则代理捷径。未知设施状态可按固定规则前往观察，固定设施 ID 决定平局。

预测的作用：将 Alice 可能承担的任务和目标设施暂时降优先级，Bob 选择可做的其他环节；若自身持物必须使用该设施，可延后或选择另一合法设施。预测不是永久禁令。

| 预测 | Bob 的主要配合 |
|---|---|
| FETCH / GET_DISH | 避开同一取物入口，选其他可执行环节 |
| PLACE / COOK_START | 暂时让出目标锅入口，服务其他锅或准备餐具 |
| PICKUP / DELIVER | 让出锅或出餐通道，承担备料等环节 |
| PRE | 考虑补料/开另一锅等可执行任务，避免重复占据等待区 |
| HOLD / unknown | 使用基础优先级 |

预测任务保留最多 12 tick；可见事实冲突、任务完成或新预测到来时解除。目标 unknown 时只调整任务类型，不凭空指定锅。连续 3 tick 无位移且目标未完成时启用固定避让；避让不读取 Alice 私有路线。上述优先级、超时在开发阶段用人工给定标签做分支验收。

加入 **Oracle 诊断**：执行器获得真实意图和真实设施，Qwen 不接收真值。它检验控制器能否利用正确预测；由于规划器可能次优，Oracle 分数是参考表现，不保证数学上最高。若 Oracle 在开发集不优于无印象，先报告配合规则缺乏效果，修改后再冻结，不解释为动机已失败或已成立。

## 9. 完整合作局的提问时机与分数【审核项 4】

B 从随机合法起点运行，不依赖隐藏 decision_id 通知 Bob。

- Alice 连续两帧可见后，如可见持物发生变化、可见设施交互、或移动方向转折，产生候选触发；首次连续看见伙伴也可触发一次。
- 两次提问至少间隔 8 tick；同一可见变化片段去重。每局最多 12 次提问，达到上限后沿用基础控制器与尚有效的预测。
- 因而 B 评估的是这个固定调用预算下的 Bob；“8 tick/12 次”属于待审核参数。A/D 的离线事件选择可使用实验标签定位真实任务边界，B 在线触发只能使用公开变化。
- 每个触发请求 3 次并投票，环境在请求期间暂停；得分按模拟 tick 计，API 实际延迟另报。Qwen 失败使用 unknown 回退，保留该局。
- 记录提问是否对应真实意图变化、遗漏与重复。B 的准确率按各条件实际触发事件描述；因为行动会改变后续轨迹，不能把不同条件的第 k 次触发当成同一个配对事件。

每组 16 起点×旧/新/无印象 = 48 局，全部 432 局；另跑相同起点的 Oracle 144 局，不调用 Qwen。全部运行 700 步，**主得分为前 300 步累计奖励**，700 步奖励为辅助；完成前 5 份汤时间未达到者记右删失，不填 0。堵塞按连续 3 tick 请求移动但未移动记一次，恢复移动后才可再次计数。

B 开发门槛：16 个开发起点中至少 12 局有一次公开触发，平均每局至少 3 次，且有效触发不全来自一个位置分区。门槛不足如实报告，不能将 Bob 瞬移到 Alice 身边补采样。

## 10. 数据分析与结论边界

- A 意图准确率：450 个事件，弃答/无效算错误；主比较 Updated−Stale。分别展示 9 组、3 张地图、8 类意图的样本数与效果，缺类写 N/A。
- A-score：同一快照、同一 post Alice，旧/新/无印象各使用自己的固定预测续局 200 tick；从快照保留的任务/计时状态继续，明确调整评估截止时间，不能因源 episode 已近 700 步而提前结束。奖励从续局开始归零统计。
- D：同一批事件比较三个条件，给总体和逐类准确率、混淆矩阵；属于一般可见决策诊断，50/组不足以保证每类精确估计。
- B：同一起点的总分可配对，各条件事件级准确率不强行配对。
- 主效应报告差值和区间。固定三张地图时，在每张地图内重采样训练实例，再重采样来源 episode/状态族（A）或起点（B），10,000 次，seed=18999。区间仅描述这三张地图和少量训练实例，不声称地图总体泛化。
- 逐组 McNemar 不一致计数表帮助解释猜对/猜错变化；不把 450 个相关事件直接当作独立训练重复求极小 p。配对得分报告均值差、正/零/负的起点或组数。
- 若补充显著性检验，用 9 个组合的条件交换进行 512 种符号翻转，报告对组间独立/交换对称假设的依赖与少量组的限制；A 准确率、A-score、B 得分三个预指定主比较用 Holm 校正。所有检验双侧，不依据观察结果切换方向。
- 450 是已定资源规模，尚无基于独立训练实例的功效保证；M17 的大效应不能用于保证 M18 必然显著。显示所有失败组与流程损耗。

三张图上多数训练实例同向、D/B 也有改善，支持更广的现象；只在 A 有改善时，结论限于配对歧义局面；若猜测改善但分数不变，需检查控制器与任务条件；若没有改善，保留反例并分析印象质量、类别与可见性。

## 11. 调用量与运行安排【审核项 5】

建议主实验先用旧/新/无三个条件，每输入三次请求。

| 阶段 | 计划请求量 |
|---|---:|
| 开发：每组 20 事件×3 条件×3 次 | 1,620 |
| A：450×3×3 | 4,050 |
| D：450×3×3 | 4,050 |
| A-score 与 Oracle | 0，复用预测或本地真值 |
| B：9×16 起点×3 条件×最多 12 触发×3 次 | 最多 15,552 |
| 合计，不含传输重试 | 最多 25,272 |

建议总请求硬上限 **28,000 次**（含失败与重试）；历史构建只用程序摘录，不调用模型。允许先批准开发+A+D的阶段，上述三项合计 9,720 次，A-score 可随后本地运行；B 是额外的主要预算来源。

正式费用按 `输入 token/百万×输入单价 + 输出 token/百万×输出单价` 估算；单价、缓存折扣与真实 prompt 长度尚未在当前服务核实，**不把调用数换算成虚构人民币金额**。用户已接受预算安排并明确费用不用担心；执行时核对价格、记录实际 token 和请求次数，在已批准的 28,000 次上限内推进，不重复索取相同授权。输入预算每请求最多 4,096 tokens（含系统文本），超限只按固定规则截断历史，不裁掉当前事实。

训练 9 条链顺序运行，避免小显存下并发；每条 400 个 PPO rollout 局，加 BC/验证/评估。墙钟耗时待首个开发阶段测量，不承诺完成时间。API 顺序或最多 2 并发，请求顺序按事件/条件平衡随机化，独立重复不能被本地缓存合并。写入每次请求、时间、响应和 usage；断点续跑只跳过已完成请求 ID。
