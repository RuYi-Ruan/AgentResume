## 为什么这样设计

### 1. 第一动作不能直接锁定意图

中心区域到设施的路线会先共用一段通道，再在较远处分叉。例如：

- 向上走可能是去左锅、中锅、右锅，也可能最终去左右洋葱台；
- 向下走可能是拿盘，也可能是去底部上菜口；
- 向左或向右走可能是去侧面上菜口，也可能绕向原料或锅。

因此 Bob 看到 Alice 的第一步时，通常还不能直接确定最终意图和设施。

### 2. 设施有真正的选择空间

旧地图里某类设施往往只有一个明显目标。新图中同类设施有多个，Bob 需要区分例如：

- `left_onion / right_onion`；
- `left_pot / middle_pot / right_pot`；
- `left_dish / middle_dish / right_dish`；
- 不同上菜口。

这让“目标设施预测”能够真正参与分流，而不是意图名称的重复答案。

### 3. 有共享通道，但不是单格死胡同

上下区域都有横向走廊，左右侧通道宽于第一张被淘汰的候选图。洋葱、锅和盘子不再完全按上下工作区分离，而是交错放置，使主厨和上菜伙伴的正常路线自然相遇；中部障碍让路线先重合再分叉，但仍保留多个绕行方向。

## 当前检查结果

- 所有行宽均为 11，地图可以被 Overcooked 环境正常加载；
- 可行走格：37；
- 所有锅、洋葱台、盘子台和上菜口均可达；
- 仅按几何最短路径检查，“位置 + 第一移动方向”同时可能通往两类以上设施的比例约为 78.4%；
- 修复通用执行器的边缘转身后，固定主厨/上菜控制器在 16 个随机起点下稳定完成任务：保守参考约 13 碗，并行参考约 22 碗；
- 若只允许在意图开始的第一步观察，3×3 可见事件过少；改为“每段意图内首次亲眼看到的新动作”后，交错布局的初步可见率约为 13%–22%。该值仍需用正式 Alice 轨迹重新检查。

最后一项不是正式基线。旧状态机含有原地图专用站位和换角色逻辑，不能用于判断新地图难度；下一步需要实现无固定坐标的通用 oracle 控制器，并按 M16 门槛验证其稳定吞吐。

## 第一张候选图为何被淘汰

第一张图为 9×7、只有 27 个可行走格。虽然几何歧义达到约 84.8%，但旧控制器在 16/16 局均发生长期阻塞，全部得分为 0。它把“意图难猜”和“根本无法合作”混在了一起，因此不再使用。

## 地图通过审核后的下一步

1. 写入正式布局常量并增加地图连通性测试；
2. 实现不依赖固定坐标的 oracle Bob 控制器；
3. 验证 oracle 明显优于随机预测，且正确设施预测确实降低冲突；
4. 采集真实轨迹，检查手持物与局面约束后仍有足够模糊事件；
5. 若上述门槛通过，再从头训练 Alice-pre 与 Alice-post；
6. 最后才整理旧/新 impression，并开始 Qwen3.5-9B 固定事件实验。
