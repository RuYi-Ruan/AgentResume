# AgentResume 最终实验说明

> 整理日期：2026-09-12  
> 当前实验版本：M17  
> 核心问题：Alice 能力提升以后，如果 Bob 对 Alice 的印象仍停留在过去，Bob 是否会误解 Alice 当前动作背后的意图，并因此影响两人的合作得分？

## 1. 实验结论概览

当前实验结果支持我们的核心 Motivation：

> Alice 成长以后，过时印象会明显误导 Bob 对 Alice 动作意图的判断；更新印象不仅提高了 Bob 的意图判断准确率，也提高了随后合作过程中的团队总分。

最核心的结果如下：

| Bob 使用的条件 | 意图准确率 | 目标设施准确率 | 后续平均上菜数 | 后续平均总分 |
|---|---:|---:|---:|---:|
| 旧印象 | 17.50% | 11.25% | 5.025 | 100.5 |
| 新印象 | 70.00% | 50.00% | 5.300 | 106.0 |
| 无印象 | 61.25% | 45.00% | 5.200 | 104.0 |

新印象相对旧印象：

- 意图准确率提高 52.5 个百分点；
- 后续平均多完成 0.275 份汤，即多获得 5.5 分；
- 80 个相同局面中，新印象在 20 个局面得分更高，57 个相同，只有 3 个更低；
- 得分差异的精确符号检验为 `p=0.000488`。

## 2. 方案是怎么一步步演进的

当前方案并不是一开始就确定的。我们先后尝试了“双方都是代码规则”“双方都是大模型”“可训练 Alice 与 MLP Bob”，最后才形成现在的“可训练 Alice + Qwen Bob + 固定执行器”。早期方案的结果主要用于发现问题和改进设计，不与 M17 正式结果混在一起。

| 阶段 | Alice | Bob | 主要优点 | 暴露的问题 | 如何影响下一版 |
|---|---|---|---|---|---|
| 规则智能体阶段 | 手写状态机 | 手写规则或统计模型 | 稳定、可解释、容易构造前后差异 | Alice 的“成长”来自人工换规则，不是训练获得 | 保留作专家数据、执行器和机制验证工具 |
| 双 LLM 阶段 | Qwen 读取经验文本后决策 | Qwen 根据经验和共享信息猜意图 | 经验和印象可以直接用自然语言表达 | Alice 能力提升不稳定；模型随机性、API、提示词和死锁都会影响结果；旧实现还向 Bob 暴露了 Alice 的决策通知 | 不再让 LLM 同时承担能力成长、意图理解和动作控制 |
| MLP 探索阶段 | 行为克隆后继续 PPO | 条件 MLP 猜意图 | Alice 的能力提升变得稳定、可复现 | Bob 的 impression 曾是直接给定的 pre/post 身份；加入全局状态和动作后，答案又几乎被直接暴露 | 印象必须来自 Bob 的真实观察，当前信息必须保持歧义 |
| M17 最终方案 | 可训练 MLP：BC 得到 pre，PPO 得到 post | Qwen 根据局部可见历史猜意图；固定控制器负责行动 | 能分别检验能力提升、意图理解和合作后果 | 随机完整对局中可见关键事件仍然太少 | 使用严格配对关键事件，并如实限制结论范围 |

### 2.1 第一阶段：Alice 和 Bob 都由代码规则实现

最初的 Alice 使用 `CookAgent` 状态机。我们手工设计了两套行为：

- L0 Alice 按较保守的顺序串行做饭；
- Lk Alice 会利用等待时间并行准备另一口锅。

Bob 同样依赖手写规则或基于轨迹统计的预测器。这个阶段确实能制造一种直观现象：面对相同局面，过去的 Alice 会等待，新的 Alice 会去取洋葱；如果 Bob 仍按旧模式理解 Alice，就会猜错。

但它只能说明“这种机制可能存在”，不能作为最终证明。因为 Alice 并没有通过学习获得能力，所谓成长只是我们把她从一套状态机切换到了另一套状态机。模型行为过于整齐，也容易让分类准确率显得过高。

这套代码没有被丢弃。它后来继续用于生成行为克隆数据、检查地图、测试寻路和验证实验流程。

### 2.2 第二阶段：Alice 和 Bob 都采用大模型

随后尝试让 Alice 和 Bob 都使用 `Qwen/Qwen3.5-9B`：

- Alice 从自然语言经验库中检索经验，并据此选择宏观任务；
- Bob 分为 unaware 和 aware 两种条件，aware Bob 获得同一份经验，并尝试推测 Alice 的意图；
- 只有宏观决策交给 LLM，底层移动仍由执行器完成。

这种方式的优点是语义非常直观：经验和印象都可以直接写成文字，Bob 也能够用自然语言解释 Alice。

实际运行后发现，它不适合独自承担严格的因果验证：

1. 给 Alice 注入经验后，行为会改变，但团队上菜能力不一定稳定提高；
2. 结果容易受到采样随机性、提示词表达、模型服务和局部死锁影响；
3. 一局需要多次调用 API，运行慢且成本较高；
4. 旧实现通过共享意图板通知 Bob“Alice 刚刚做了新决定”，这比现实合作中 Bob 亲眼观察动作获得的信息更充分；
5. 早期实验还出现过把同一意图的连续 tick 重复计分等口径问题。

因此，双 LLM 结果只保留为探索记录，不能作为最终统计。它促使我们把三个问题拆开：Alice 是否真的成长、Bob 是否理解正确、理解是否真正改善合作。

### 2.3 第三阶段：可训练 Alice 与 MLP Bob

接下来参考 RECOLLAB 的思路，把伙伴印象表示为对 Alice 类型的结构化 belief，并开始训练真正的 pre/post Alice：

- Alice 先通过行为克隆得到成长前 checkpoint，再通过 PPO 继续训练得到成长后 checkpoint；
- Bob 使用 MLP，根据厨房状态和一个表示 `pre/post` 的 impression 向量预测 Alice 意图。

这一阶段解决了最重要的问题：Alice 的能力提升现在来自训练，并且可以在独立 seed 上稳定复现。但 Bob 的设计仍然不符合最初问题。

M14 中的 impression 是实验直接给定的 pre/post one-hot 身份，相当于提前告诉 Bob“Alice 属于哪一类”，不是 Bob 从相处历史中形成的印象；输入里也没有 Alice 刚刚做出的动作。M15 加入了 Alice 的动作和动作前后全局状态，但信息过于充分，旧印象、新印象和无印象准确率都约为 99.97%，Bob 几乎不需要使用印象。此外，更高的意图准确率没有转化成更高得分，暴露出 Bob 控制器没有正确利用预测。

这些失败帮助我们确定了两个原则：不能直接把 Alice 身份当作印象输入，也不能给 Bob 足以直接看穿答案的全局信息；意图准确率和团队得分必须同时验证。

### 2.4 最终采用的混合方案

M17 最终把不同模块各自放在更适合的位置：

```text
可训练 MLP Alice
负责产生稳定、可复现的能力成长
             ↓
Bob 的3×3可见历史
负责形成旧印象或新印象
             ↓
Qwen Bob
负责结合印象解释当前动作背后的意图
             ↓
固定宏观控制器
负责把预测转换成互补任务和避让行为
```

最终选择是：

- **Alice 使用 MLP**：行为克隆得到成长前模型，再用 PPO 训练出能力更强的成长后模型；
- **Bob 使用 Qwen 做理解**：印象来自 Bob 亲眼看到的结构化历史，调用时转换成 JSON 文本上下文；
- **Bob 使用固定代码做行动**：根据 Qwen 预测选择互补任务，避免把 LLM 的规划波动混入意图实验；
- **严格隔离隐藏信息**：Qwen 看不到 Alice 的真实意图、内部目标、网络权重和视野外轨迹。

这个组合不是为了证明某一种模型最好，而是为了把研究问题拆得足够清楚：Alice 的成长由训练保证，Bob 的语义理解由 LLM 完成，合作得分则由统一的执行规则检验。

## 3. 实验环境

### 3.1 游戏与地图

实验基于 Overcooked-AI，使用自定义的 `AMBIGUOUS_KITCHEN_V2` 地图。地图大小为 11×7，包含：

| 设施 | 数量 |
|---|---:|
| 洋葱台 | 2 |
| 锅 | 3 |
| 盘子台 | 3 |
| 出餐口 | 4 |

地图中间包含墙体和狭窄通道。多个锅、洋葱台和出餐口使 Alice 的同一个移动动作可能对应不同目标，避免 Bob 只看一步动作就直接知道答案。

### 3.2 基本运行设置

| 项目 | 设置 |
|---|---|
| Python | 3.11 |
| Overcooked-AI | 1.1.0 |
| Alice 常规训练/评估长度 | 每局 700 步 |
| 在线得分续局长度 | 观察动作后继续 200 步 |
| 一份汤的奖励 | 20 分 |
| 总体随机种子 | 20260913 |
| Qwen 模型 | `Qwen/Qwen3.5-9B` |
| Qwen API | SiliconFlow OpenAI 兼容接口 |
| Qwen temperature | 0 |

Alice 的 checkpoint 元数据记录训练设备为 `cuda`。当前 conda 环境重新检查时为 PyTorch `2.1.0+cpu`，因此后续复现实验时应以 checkpoint 内保存的训练配置和结果文件为准；推理和续局本身可以在 CPU 上运行。

## 4. Alice 是怎么得到的

实验中有两个 Alice：成长前 Alice 和成长后 Alice。两者使用相同的网络结构，成长后 Alice 是在成长前 checkpoint 上继续训练得到的，不是另起一个完全无关的模型。

### 4.1 Alice 的输入和输出

Alice 使用一个小型 MLP，在关键决策时选择宏观意图。输入是 182 维厨房状态向量，主要包括：

- Alice 和 Bob 的位置；
- 两人的手持物；
- 三口锅的状态；
- 当前已经完成的菜品数；
- 当前时间进度。

Alice 的真实意图和内部目标不会作为模型输入。

MLP 结构为：

```text
182维厨房状态
      ↓
128维全连接层 + Tanh
      ↓
128维全连接层 + Tanh
      ↓
8种宏观意图
```

8 种宏观意图为：

| 意图 | 含义 |
|---|---|
| `FETCH` | 去拿洋葱 |
| `PLACE` | 把洋葱放入锅中 |
| `COOK_START` | 启动烹饪 |
| `GET_DISH` | 去拿盘子 |
| `PICKUP` | 从锅中盛汤 |
| `DELIVER` | 把汤送到出餐口 |
| `PRE` | 在正在烹饪的锅附近等待或照看 |
| `HOLD` | 暂时等待或让行 |

宏观意图选定后，由固定路径执行器把它转换成上、下、左、右、停留和交互等具体动作。

### 4.2 成长前 Alice

成长前 Alice 通过行为克隆训练得到：

1. 使用保守型 L0 规则专家玩 Overcooked；
2. 专家倾向于照看正在烹饪的锅，在部分关键局面选择 `PRE`；
3. 只在专家开始一个新宏观任务时保存“厨房状态—宏观意图”样本；
4. 使用这些样本训练 MLP 模仿专家。

具体配置如下：

| 配置项 | 数值 |
|---|---:|
| 训练局数 | 24 |
| 训练 seed | 9101—9124 |
| 独立测试局数 | 16 |
| 测试 seed | 9201—9216 |
| 训练决策样本 | 4189 |
| 测试决策样本 | 2986 |
| Epoch | 100 |
| Batch size | 256 |
| 优化器 | Adam |
| 学习率 | 0.003 |
| Weight decay | 0.0001 |
| 损失函数 | 带类别权重的交叉熵 |
| 隐藏层宽度 | 128 |

行为克隆离线训练集和测试集准确率均为 100%。在对应闭环测试中，成长前 Alice 平均完成 12.625 份汤。

### 4.3 成长后 Alice

成长后 Alice 从成长前 checkpoint 继续使用 PPO 训练。训练目的不是让它“故意改变性格”，而是直接提高团队上菜能力。

| 配置项 | 数值 |
|---|---:|
| PPO 更新次数 | 50 |
| 每次更新采集局数 | 8 |
| 每局长度 | 700 步 |
| 学习率 | 0.0003 |
| 折扣因子 `gamma` | 0.995 |
| GAE `lambda` | 0.95 |
| 动作温度 | 5.0 |
| 熵系数 | 0.08 |
| 单个宏观任务最长时间 | 50 步 |
| 验证 seed | 9501—9516 |
| 测试 seed | 9601—9616 |
| checkpoint 选择规则 | 固定验证集平均上菜数最高 |
| 最佳 checkpoint | 第 25 次更新 |

选择 checkpoint 时只查看 Alice 在固定验证集上的上菜能力，没有使用 Bob 的意图预测结果，也没有根据正式测试答案挑选模型。

在相同的 16 个测试 seed 上：

| Alice | 平均上菜数 | 最少 | 最多 |
|---|---:|---:|---:|
| 成长前 checkpoint | 12.8125 | 12 | 14 |
| 成长后 checkpoint | 17.9375 | 17 | 18 |
| 成长带来的变化 | **+5.125** | — | — |

16 个测试 seed 中，成长后 Alice 在全部 16 个 seed 上都优于成长前 Alice。配对 bootstrap 95% 区间为增加 4.6875—5.5625 份汤。因此实验中的“能力提升”是实际训练得到并单独验证过的。

## 5. Bob 是怎么设置的

本实验中的 Bob 分为三个相互衔接的部分。

### 5.1 观察历史的 Bob

形成印象时，Bob 使用固定的局部跟随/中央观察策略：

- Bob 只能看到自己周围的 3×3 区域；
- 只能记录 Alice 的可见位置、手持物和真实动作结果；
- 锅状态必须是 Bob 亲眼看见过的，并保存观察时间；
- Alice 一旦离开视野，当前历史片段立即结束；
- Alice 后来重新出现时另开新片段，不能补写中间发生了什么；
- Bob 不读取 Alice 的网络、真实宏观意图、内部目标或视野外轨迹。

旧印象只来自成长前 Alice，新印象只来自成长后 Alice。

### 5.2 猜意图的 Bob

意图预测由 `Qwen/Qwen3.5-9B` 完成。Qwen 接收到：

1. Bob 动作前的局部观察；
2. Alice 在环境中真正完成的第一步动作；
3. Bob 动作后的局部观察；
4. 已知静态地图设施；
5. 旧印象、新印象或不提供印象；
6. 最多 5 个与当前动作相近的历史可见片段。

Qwen 只需要判断两个核心意图：

| 输出 | 含义 |
|---|---|
| `PRE` | Alice 准备在锅附近等待或照看，应由 Bob 去拿洋葱 |
| `FETCH` | Alice 准备自己去拿洋葱，Bob 应做其他互补任务 |

Qwen 还会辅助预测 Alice 前往的具体设施，但不会预测精确坐标。

返回格式被限制为：

```json
{
  "intent": "PRE 或 FETCH",
  "target_facility": "设施名称或 unknown",
  "confidence": 0.0,
  "used_fact_ids": ["实际引用的事实编号"]
}
```

程序会拒绝额外字段、非法意图、非法设施、虚构事实编号或自由发挥的解释。非法输出最多重试一次，仍然非法就记作错误。

### 5.3 执行配合的 Bob

Qwen 的预测会交给固定的宏观控制器：

| Bob 猜到的 Alice 意图 | Bob 的配合行为 |
|---|---|
| `PRE` | Bob 接下“取一颗洋葱并送锅”的任务 |
| `FETCH` | Bob 不再重复取洋葱，改做拿盘子、盛汤和出餐 |

如果 Qwen 预测了目标设施，Bob 会尽量避免与 Alice 抢同一个入口。Bob 接下一个任务后，在任务完成前不会被新的普通预测随意覆盖。

除了输入的预测不同，旧印象、新印象和无印象条件使用的是同一个 Bob 控制器。

## 6. 印象是怎么形成的

从严格划分出的 40 对历史局面中，分别运行成长前和成长后 Alice。每段历史最多连续观察 20 步。

| 印象来源 | 历史局面 | 完整有效片段 | 主要可见结果 |
|---|---:|---:|---|
| 成长前 Alice | 40 | 35 | 21 次保持空手且未去取料；13 次到达洋葱区；其余为等待或离开视野 |
| 成长后 Alice | 40 | 35 | 34 次到达洋葱区；其余为等待或离开视野 |

这些记录中没有保存 Alice 的真实意图标签。为了确认印象确实包含可学习差异，额外使用简单逻辑回归进行 8 折配对交叉验证：

| 项目 | 结果 |
|---|---:|
| 历史记录数 | 80 |
| 总体分类准确率 | 76.25% |
| 预设通过门槛 | 75% |
| 各折准确率范围 | 70%—80% |

该门槛通过，说明单纯依靠可见历史，确实能够区分成长前和成长后 Alice，但又没有简单到完全可分。

## 7. 正式事件是怎么构造的

### 7.1 为什么需要严格配对

如果 Alice 的动作已经直接暴露目标，那么 Bob 不需要印象也能猜对，实验就失去了意义。因此只保留以下事件：

- 成长前和成长后 Alice 面对完全相同的厨房状态；
- 两个 Alice 的位置、朝向和手持物相同；
- Bob 的位置、朝向、手持物、局部观察和锅记忆相同；
- 两个 Alice 发出的第一步动作相同；
- 该动作在环境中真正执行成功；
- 第一步动作后的公开状态仍相同；
- 成长前 Alice 的意图是 `PRE`；
- 成长后 Alice 的意图是 `FETCH`；
- 两个 Alice 的内部目标设施不同。

因此，Bob 只看当前局面和第一步动作无法确定答案，必须利用过去形成的印象。

### 7.2 数据划分

共找到 154 个满足条件的候选事件，冻结为：

| 数据部分 | 数量 | 用途 |
|---|---:|---|
| 历史观察池 | 40 | 形成旧印象和新印象 |
| 开发集 | 20 | 调试格式、检查稳定性和控制器 |
| 正式测试集 | 80 | 最终结果，只运行一次 |
| 未使用候选 | 14 | 不进入当前实验 |

历史、开发和正式测试的事件 ID 完全不重叠。正式测试开始以后，没有根据正式答案修改提示词。

## 8. 实验流程

完整流程如下：

```text
L0保守专家轨迹
      ↓ 行为克隆
成长前 Alice checkpoint
      ↓ PPO继续训练
成长后 Alice checkpoint

成长前/后 Alice 分别产生局部可见历史
      ↓
旧印象 / 新印象
      ↓
Bob观察严格配对局面和Alice第一步真实动作
      ↓
Qwen预测 PRE/FETCH 和目标设施
      ↓
固定Bob控制器选择互补任务并避让
      ↓
统计意图准确率和后续团队得分
```

### 8.1 Qwen 开发检查

首先在开发集检查格式和稳定性：

- 8 个事件分别使用旧印象、新印象和无印象，每个输入重复 3 次，共 72 次；
- 72/72 回答均通过格式校验；
- 83.33% 的输入组三次答案完全一致；
- 平均多数一致率为 94.44%。

随后运行完整 20 个开发事件，共 60 次请求：

| 条件 | 成长后 Alice 意图准确率 |
|---|---:|
| 旧印象 | 20% |
| 新印象 | 65% |
| 无印象 | 60% |

开发结果通过后，提示词被冻结。

### 8.2 正式意图实验

正式测试使用 80 个未用于提示词调试的事件。每个事件分别提供旧印象、新印象和无印象，共得到 240 个回答。

所有条件中的公开局面和 Alice 动作完全相同，唯一变化是 Bob 得到的历史印象。Alice 的真实意图只在 Qwen 回答之后用于计算准确率，从未进入提示词。

### 8.3 合作得分实验

最初计划从随机合法起点运行完整对局。但开发检查发现：8 局中 Alice 产生了 1071 次新宏观决策，Bob 只有 1 次恰好位于 Alice 的 3×3 可见范围，因此无法形成足够的自然关键事件。

为了不扩大 Bob 视野、不瞬移智能体、不读取隐藏状态，最终改为严格配对续局：

1. 从冻结的关键局面开始；
2. Bob 原地观察 Alice 真正完成第一步动作；
3. Bob 接收一次已保存的 Qwen 意图预测；
4. Alice 和 Bob 从该状态继续合作 200 步；
5. 统计后续完成的汤和环境总分。

正式得分实验直接复用意图实验保存的 Qwen 回答，没有再次调用 Qwen，也没有重新挑选事件。

## 9. 实验结果

### 9.1 Alice 确实获得了能力提升

| 指标 | 成长前 Alice | 成长后 Alice | 差值 |
|---|---:|---:|---:|
| 配对测试平均上菜数 | 12.8125 | 17.9375 | +5.125 |
| 上菜数范围 | 12—14 | 17—18 | — |
| 得到提升的测试 seed | — | 16/16 | — |

### 9.2 正式意图预测结果

| Bob 条件 | 正确数 | 意图准确率 | 目标设施准确率 |
|---|---:|---:|---:|
| 旧印象 | 14/80 | 17.50% | 11.25% |
| 新印象 | 56/80 | 70.00% | 50.00% |
| 无印象 | 49/80 | 61.25% | 45.00% |

新印象相对旧印象提高 52.5 个百分点，配对 bootstrap 95% 区间为提高 41.25—63.75 个百分点。

| 新旧印象逐事件比较 | 事件数 |
|---|---:|
| 新旧都正确 | 14 |
| 只有旧印象正确 | 0 |
| 只有新印象正确 | 42 |
| 新旧都错误 | 24 |

精确 McNemar 双侧检验为 `p=4.55e-13`。

完整交叉检查中：

| 印象是否与真实 Alice 匹配 | 准确率 |
|---|---:|
| 匹配 | 76.25% |
| 不匹配 | 23.75% |

这说明 Qwen 不是固定回答某个意图，而是在明显受到伙伴印象影响。

### 9.3 Bob 控制器有效性检查

正式计算团队得分前，先在 20 个开发局面比较完全正确预测和故意相反预测：

| 条件 | 平均上菜数 | 平均总分 |
|---|---:|---:|
| 完全正确预测 | 5.35 | 107 |
| 故意相反预测 | 4.20 | 84 |
| 差值 | +1.15 | +23 |

20 个局面中，正确预测在 8 个局面更好、11 个相同、1 个更差。说明 Bob 的控制器确实能够把意图预测转化成不同的合作行为。

### 9.4 正式合作得分结果

| Bob 条件 | 意图准确率 | 平均上菜数 | 平均总分 |
|---|---:|---:|---:|
| 旧印象 | 17.50% | 5.025 | 100.5 |
| 新印象 | 70.00% | 5.300 | 106.0 |
| 无印象 | 61.25% | 5.200 | 104.0 |

配对比较如下：

| 比较 | 平均上菜数差 | 平均分数差 | 95%区间（上菜数） | 更好/相同/更差 | `p`值 |
|---|---:|---:|---:|---:|---:|
| 新印象 − 旧印象 | +0.275 | +5.5 | +0.125～+0.450 | 20/57/3 | 0.000488 |
| 新印象 − 无印象 | +0.100 | +2.0 | -0.0375～+0.275 | 10/65/5 | 0.3018 |
| 无印象 − 旧印象 | +0.175 | +3.5 | +0.050～+0.300 | 17/58/5 | 0.0169 |

新印象相对旧印象的提升稳定；新印象虽然平均优于无印象，但当前差异还不够稳定。无印象也显著优于旧印象，说明过时印象并非只是“没有帮助”，还可能主动误导 Bob。

## 10. 最终结论

当前实验在以下范围内验证了 Motivation：

> 在严格配对、Bob 能够亲眼看到 Alice 第一步真实动作的关键决策局面中，Alice 能力提升后，过时印象会使 Bob 更容易把 Alice 的新行为解释成旧意图；更新印象能够显著提高意图判断准确率，并提高随后 200 步的团队合作得分。

实验支持的完整因果链为：

```text
Alice经过训练获得能力提升
          ↓
Alice在相同局面中的行为意图发生改变
          ↓
旧印象让Bob继续按照过去理解Alice
          ↓
Bob更容易猜错Alice动作背后的意图
          ↓
Bob选择了不合适或重复的任务
          ↓
团队总分下降
```

论文中建议使用“得到实验支持”或“在当前实验设置下得到验证”，不建议写成不受条件限制的“完全证明”。目前尚未证明：

- 该现象在所有地图上都成立；
- 对所有 Alice、Bob 或 LLM 都成立；
- 在随机起点的完整自然对局中同样稳定成立；
- 新印象一定显著优于完全不使用印象。

这些限制不否定当前 Motivation。现有结果已经同时证明了三个关键环节：Alice 真的成长了、过时印象真的降低了意图理解、理解错误真的会进一步影响合作得分。
