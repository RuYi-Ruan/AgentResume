# M17 实验设计（待审核）

> 状态：方案已审核通过；固定事件意图实验和固定关键局面续局得分实验均已完成；随机起点完整对局因可见事件不足暂未验证。  
> 核心问题：Alice 能力提升后，如果 Bob 对她的印象仍停留在过去，Bob 对 Alice 当前动作背后意图的理解会不会变差，并进一步影响合作得分？

## 1. 这次到底要验证什么

我们只验证下面这条链路：

```text
过去亲眼见过的 Alice 行为
        ↓
Bob 形成旧印象或新印象
        ↓
Bob 看见 Alice 在关键时刻做出的动作
        ↓
Bob 猜 Alice 接下来真正想做什么
        ↓
Bob 据此选择互补任务和避让路线
        ↓
意图准确率、团队得分发生变化
```

其中：

- **旧印象**只来自成长前 Alice 的可见历史；
- **新印象**只来自成长后 Alice 的可见历史；
- Bob 不知道 Alice 的策略网络、宏观意图、隐藏状态或真实目标；
- Bob 只能使用自己实际看见的行为和当前局部观察；
- 核心比较是成长后 Alice 搭配“旧印象 Bob”与“新印象 Bob”。

## 2. 为什么要拆成两个阶段

上一版把一段自然语言印象直接塞给 Qwen，来源和含义都不够稳定。M17 改成两步：

### 第一步：形成伙伴印象

Bob 根据过去若干段连续可见的 Alice 行为，得到一个可保存的行为印象。例如：

```text
在 18 次可观察的相似局面中：
- Alice 有 12 次进入锅边后继续停留；
- 有 3 次转向洋葱区；
- 有 3 次因为离开视野而无法判断后续。
```

这里先保存事实统计和原始短片段，不让 Qwen自由发挥写人物故事。

### 第二步：解释当前动作

到了正式关键事件，Qwen 同时看到：

1. Bob 当前 3×3 视野内的事实；
2. Alice 刚刚真实完成的动作，而不是策略发出的、可能被挡住的动作指令；
3. 已冻结的旧印象、新印象或无印象；
4. 3—5 个与当前局面相近的历史片段。

然后只回答：

```json
{
  "intent": "PRE 或 FETCH",
  "target_facility": "具体设施编号或 unknown",
  "confidence": 0.0,
  "used_fact_ids": ["F1", "H3"]
}
```

`PRE` 表示 Alice 准备在锅边等待/配合，由 Bob 去取洋葱；`FETCH` 表示 Alice 打算自己去取洋葱。`target_facility` 是对目标设施的推测，允许目标暂时在视野外，但必须明确属于“推测”，不能伪装成 Bob 已经看见的事实。

## 3. 印象数据如何产生

继续使用现有成长前、成长后 Alice checkpoint，不重新训练 Alice。

分别让 Bob 与成长前、成长后 Alice 进行独立的历史合作局：

- Bob 仍然只有 3×3 视野；
- Bob 使用同一套固定的“中央支援/观察”策略，不追着标签走，也不读取 Alice 隐藏状态；
- Alice 一旦离开视野，当前片段立即结束，之后重新出现时另开片段；
- 只记录动作执行后的真实位置、手持物变化、交互结果和可见设施；
- 无法看见后续时明确记为 `unknown`，绝不补齐；
- 成长前和成长后使用相同数量、相同 seed 规则的历史局。

先设置一道可观测性门槛：每类 Alice 至少得到 30 段完整、连续可见、与 PRE/FETCH 区分有关的短片段。如果现有地图和 Bob 路线做不到，就先调整历史局中的 Bob 支援路线；仍做不到再讨论地图，而不是伪造观察。

印象数据和正式测试事件必须来自不同 seed、不同 episode，不能互相复用。

## 4. 固定事件实验：先单独验证“旧印象会不会误导”

这是最重要、也最干净的一步。

每对事件必须满足：

- 厨房公开状态相同；
- Bob 的位置、朝向、手持物和记忆相同；
- Alice 的位置、朝向和手持物相同；
- Alice 实际完成的第一步动作相同；
- 但成长前 Alice 的真实意图为 `PRE`，成长后 Alice 的真实意图为 `FETCH`；
- 第一步执行后的公开状态仍相同。

也就是说，单看眼前这一小步，答案不能被直接看穿；Bob 必须借助对 Alice 的既有印象来解释。

### 条件设置

每个事件都跑以下条件：

| 真实 Alice | 提供给 Bob 的印象 | 含义 |
|---|---|---|
| 成长前 | 旧印象 | 印象匹配 |
| 成长前 | 新印象 | 印象不匹配 |
| 成长后 | 旧印象 | 核心的“印象过时”条件 |
| 成长后 | 新印象 | 核心的“印象已更新”条件 |
| 两者 | 无印象 | 判断当前动作本身能提供多少信息 |

主比较是：**成长后 Alice：新印象 vs 旧印象**。

完整交叉条件用于排除一种假象：Qwen 无论看见什么都固定回答 `FETCH`，碰巧在成长后事件上得分很高。

### 数据划分

- 已被两轮 pilot 看过的 4 对事件：只留作开发调试，并永久排除在正式测试外；
- 再选 16 对作为开发集，用于修格式和提示词；
- 从未看过的候选中冻结 80 对作为正式测试集；
- 正式测试开始后不再根据答案改提示词；
- 四个移动方向、不同锅和不同洋葱设施尽量平衡。

## 5. Qwen 如何防止脑补

只靠一句“禁止脑补”不够，程序也要限制输出：

- 当前事实由程序编号为 `F1、F2……`；历史事实编号为 `H1、H2……`；
- Qwen 只能通过 `used_fact_ids` 引用证据，不能自己新增事实；
- 输出中不再提供会影响判定的自由文本理由；
- JSON 字段、枚举值和证据编号全部做硬校验；
- 非法输出自动重试一次，仍非法就记为 `invalid`，不能计入正确；
- “看见的设施”和“推测的目标设施”分开保存；
- 温度固定为 0，保存完整请求、响应、模型名、时间和提示词哈希。

正式实验前，在开发集的 8 对事件上重复调用 3 次，检查相同输入是否稳定；这一检查只看稳定性和格式，不拿正式测试集调参。

## 6. 不能只测 Qwen

同一份输入还要跑三个参照组：

1. **无印象 Qwen**：确认当前动作本身是否已经泄露答案；
2. **简单分类器**：用相同的可见历史统计和当前动作训练逻辑回归，不使用隐藏状态；
3. **Oracle 上限**：直接给控制器正确意图，只用于确认“如果猜对，配合确实会变好”，不参与主结论。

这样可以区分三种情况：

- Qwen 和简单分类器都能测出差异：motivation 得到较强支持；
- 简单分类器能做到、Qwen 做不到：问题主要在 LLM 表达或推理链路；
- 两者都做不到：印象数据本身没有提供足够证据，不能硬说 motivation 不成立。

## 7. 在线合作实验：再验证“猜错是否真的影响配合”

只有固定事件实验通过数据质量检查后才进入在线实验。

成长后 Alice 固定不变，Bob 分成：

- 旧印象 Bob；
- 新印象 Bob；
- 无印象 Bob；
- Oracle Bob（正确意图上限）。

四组使用同一批随机合法起点和配对 seed。Bob 只在 Alice 的宏观意图新开始、且亲眼看见 Alice 的第一步真实动作时预测一次；同一意图持续期间不重复猜。

Bob 的配合规则冻结为：

- 预测 `PRE`：Bob 优先取洋葱并送往对应锅；
- 预测 `FETCH`：Bob 改做盘子、出餐、其他锅支援或避让；
- 预测到目标设施后，在路径规划中避免与 Alice 抢同一入口；
- Bob 一旦接下任务，在任务完成前忽略新的普通预测；只有任务已经不合法或角色相撞时才允许中断，并记录原因。

正式实验一次性冻结 64 个配对 seed，不在看到中途结果后临时挑 seed、删 seed 或决定是否追加。

### 实际执行时的预注册修订

随机起点开发检查实际运行了 8 局。在 1071 次 Alice 新宏观决策中，Bob 只有 1 次处于 Alice 的 3×3 可见范围，没有形成可比较事件。因此没有继续运行 64 个 seed，也没有扩大 Bob 视野或向其暴露隐藏状态。

替代实验复用已经冻结的严格配对关键局面：Bob 原地观察 Alice 第一步真实动作，接收一次预测后，从该完全相同的局面继续合作 200 步。先用 20 个开发局面比较 Oracle 与故意相反预测，通过控制器闸门后，再一次性运行 80 个正式局面的旧印象、新印象和无印象条件。该修订检验的是“关键事件之后的得分影响”，不冒充随机起点完整对局。

## 8. 最终统计什么

### 两个主指标

1. **Bob 意图猜测准确率**：重点报告成长后 Alice 上新印象与旧印象的配对差值；
2. **团队总得分**：用完成菜品数为主，同时保留环境原始 reward。

### 辅助指标

- 具体目标设施预测准确率；
- `invalid` 或证据越界比例；
- Bob 与 Alice 堵塞/抢路次数；
- Bob 接受、完成和中断任务的次数；
- Qwen 的置信度是否可信；
- 简单分类器、无印象和 Oracle 的结果。

准确率和得分都按同一事件或同一 seed 配对比较，并给出误差范围，不只报一个平均数。

## 9. 开始正式实验前的程序检查

以下测试全部通过后才能调用 Qwen：

1. Alice 离开视野后，历史片段立即断开；
2. 记录的是实际动作结果，不是原始动作命令；
3. 锅记忆只能来自 Bob 曾经亲眼看见并带时间戳的状态；
4. 开发集、正式测试集和历史印象集没有 seed/episode/event 重叠；
5. 严格事件第一步执行前后都公开一致；
6. Qwen 不能引用不存在的事实编号；
7. `observed_facility` 与 `predicted_target_facility` 不混用；
8. Bob 未完成任务不会被普通新预测悄悄覆盖；
9. 每次运行保存配置、代码版本、checkpoint 哈希和原始结果。

## 10. 通过与失败怎样解释

我们不预先要求实验一定成功，而是预先规定解释方式：

- **新印象显著提高意图准确率，同时提高总得分**：完整支持当前 motivation；
- **准确率提高、得分不提高**：说明印象影响理解，但 Bob 的配合控制器还没有利用好这种理解；
- **准确率不变、得分提高**：需要检查目标设施预测或避让机制，而不能归功于意图准确率；
- **新旧印象都接近 100%**：当前动作信息仍然太充分，事件设计失败；
- **新旧印象都接近 50%，简单分类器也失败**：可观察历史不足以形成有效印象；
- **简单分类器成功而 Qwen 失败**：保留 motivation，否定当前 Qwen 实现；
- **旧印象反而更好**：先检查印象来源、事件泄漏和提示词，若均无问题，就如实报告原假设未获支持。

## 11. 本方案借鉴了什么

- ReCollab：先观察短行为轨迹形成伙伴类型判断，再切换配合策略；使用行为统计和相似轨迹例子约束 LLM；同时报告分类准确率和累计回报。
- Overcooked 人机协作工作：伙伴模型只有真正改变自己的配合策略，才可能转化为团队收益。
- 部分可观测临时组队研究：对伙伴和任务的判断应来自自身观察历史，而不是全局真值。
- 动作可读性研究：从动作前缀猜目标本来就可能含糊，因此正式测试需要刻意保留“相同动作、不同目标”的关键事件。
