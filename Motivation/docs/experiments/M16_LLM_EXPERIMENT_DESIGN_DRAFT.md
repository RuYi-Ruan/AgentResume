# M16：基于 LLM Bob 的动作—意图理解实验（待审核）

> 状态：总体方案于 2026-09-11 经用户确认；具体地图仍待审核，尚未运行正式训练或 LLM 实验。模型固定为项目已有的 `Qwen/Qwen3.5-9B`，沿用现有 API 配置。

## 1. 重新明确研究问题

Alice 经过训练后能力提高，行为习惯也发生改变。Bob 只能看到 Alice 已经表现出来的动作，并结合自己过去形成的印象理解她。

我们要验证：

```text
Alice 已成长，但 Bob 仍使用旧印象
→ Bob 更容易误解 Alice 动作背后的意图和目标设施
→ Bob 做出不合适的分工或避让
→ 团队得分下降

Bob 更新印象
→ 对同一行为的理解更准确
→ 配合改善
→ 团队得分恢复或提高
```

M15 的失败经验需要被保留：如果动作和状态已经直接暴露答案，或者 Bob 的下游配合规则不能正确使用答案，就无法验证这条链。

## 2. 总体结构

第一阶段使用“LLM 负责理解、固定控制器负责执行”的混合 Bob：

```text
有限的公开观察 + Alice 第一个动作 + Alice impression
                         ↓
                      LLM Bob
                         ↓
              意图 + 目标设施 + 置信度
                         ↓
             所有条件共用的配合控制器
                         ↓
                    Bob 实际动作
```

这样能分别检查“Bob 是否理解正确”和“理解是否改善合作”。在第一阶段成立后，才考虑让 LLM 同时负责完整行动规划；不在一开始把理解错误与规划不稳定混在一起。

## 3. Alice 需要重新训练

不直接沿用当前简单双锅地图上的 pre/post checkpoint。新地图确定后，重新建立：

- `Alice-pre`：由保守专家轨迹进行行为克隆得到；
- `Alice-post`：从同一个 pre checkpoint 继续训练，只使用团队任务奖励；
- train、validation、test seed 严格分离；
- 只根据 validation 得分选择 post checkpoint；
- 在 Bob 印象实验开始前，冻结两个 checkpoint。

能力提升门槛：在未参与训练和选模的测试 seed 上，post Alice 与同一个固定伙伴合作时，团队平均得分必须显著高于 pre Alice，并报告逐 seed 结果。若不满足，停止，不开展印象实验。

## 4. 地图设计

新地图暂称 `ambiguous_kitchen_v1`，候选布局见 `M16_MAP_PROPOSAL.md`，需满足：

- 至少两个洋葱台或原料台；
- 至少两口锅；
- 多个设施共享一段通道；
- Alice 向同一个方向迈出第一步时，可能是在执行不同意图；
- 成长前后 Alice 在相同或相近局面下，会选择不同的任务顺序；
- 不能通过手持物直接排除到只剩一个合法意图；
- 地图仍允许两个智能体通过合理分工获得稳定得分，不能靠制造死锁产生差异。

正式训练前先生成地图示意图，并用最短路径程序统计：每种“状态 + 第一动作”平均对应多少个可行意图/设施。若绝大多数事件仍只有唯一答案，地图退回修改。

## 5. Bob 能看到什么

每段 Alice 宏观意图最多询问一次。若意图开始时 Alice 已在 Bob 视野中，Bob 在观察第一个 primitive action 后被询问；若开始时不可见，则不通知 Bob 意图已经变化，等 Alice 在执行同一意图期间首次进入视野并产生一个新动作时，Bob 才根据这个亲眼看到的动作判断她当前在做什么。此前没看到的动作不会补发。

LLM 的当前事件输入包含：

- 动作发生前 Bob 的 3×3 局部视野；
- Bob 自己的位置、朝向和手持物；
- 如果 Alice 在视野中：Alice 的相对位置与手持物；
- Bob 此前亲自观察到的锅状态记忆及观察时间；
- Alice 第一个可观察动作：上、下、左、右、交互或停留；
- 厨房的静态拓扑说明，例如“左原料台”“右锅”，不提供内部路线；
- 当前条件下 Bob 持有的 Alice impression。

不提供：

- Alice 内部真实意图；
- Alice 内部 target；
- Alice 的未来动作或规划路线；
- 动作完成后的手持物变化和锅状态变化；
- 其他程序根据全局状态计算出的“合法意图集合”；
- 旧实现中的 Alice 内部意图共享面板。

如果 Alice 在整段意图执行期间都不在 Bob 视野中，Bob 不会凭空获得动作，也不会得知 Alice 刚刚改变了意图。该段记为“未观察到”，不进入预测准确率分母，不触发新预测；Bob 继续使用上一次判断或根据自己的可见状态推进安全任务。Alice 从视野外走入视野时不会补发此前动作，但她进入视野后实际产生的新动作可以触发一次“当前意图”预测。

## 6. 预测时机与事件分类

真实意图片段仍由评估器根据 `current_intent != previous_intent` 划分，但该边界不向 Bob 显示。评估器只负责保证同一意图片段最多记分一次。

```text
t：Alice 在当前意图片段内执行一个动作
   如果这是 Bob 在该片段内亲眼看到的第一个动作，则记录公开观察
t+1：LLM 预测 Alice 当前意图；预测从此刻开始影响 Bob 行动
```

事件预先分为两类：

- 简单事件：根据 Bob 当时可见的信息和第一动作，只存在一个合理意图；
- 模糊事件：至少两个意图或设施都能产生相同的第一动作。

“模糊”由地图、可见信息和最短路径计算规则预先判定，不根据 LLM 是否答错来判定，避免事后挑数据。

第一步就是 `interact` 的事件保留在总体结果中，但通常归入简单事件；主要分析另外报告模糊事件。

## 7. Impression 从哪里来

Bob 不再用带标签的 Alice 轨迹训练分类器。LLM 本身在所有条件中完全相同，只切换它收到的印象文本。印象来源也必须受 Bob 的可见范围约束：只能总结历史合作中 Bob 当时实际看见的 Alice 行为，不能使用全局录像中 Bob 看不到的片段。

印象使用与正式测试完全不重叠的历史示范局生成：

- 旧印象：只允许使用 Alice-pre 的历史行为；
- 新印象：只允许使用 Alice-post 的历史行为；
- 无印象：只说明 Alice 是一名合作伙伴，不描述她的个人习惯。

历史摘要只使用可观察行为统计，不读取 Alice 的内部 intent 标签，例如：

- 她是否经常在一锅烹饪时提前准备下一锅；
- 她通常偏向原料侧还是上菜侧；
- 她是否经常提前取盘；
- 她偏好的设施和通道；
- 她遇到拥堵时通常等待还是换路。

旧/新印象使用相同模板、相近字数和相同字段，不能把某个测试局面的正确答案直接写进印象。

## 8. LLM Bob 的输出

模型固定输出 JSON：

```json
{
  "intent": "FETCH",
  "facility": "left_onion",
  "confidence": 0.72,
  "evidence": "Alice空手并向左侧通道移动"
}
```

- `intent` 仍使用八类：`FETCH / PLACE / COOK_START / GET_DISH / PICKUP / DELIVER / PRE / HOLD`；
- `facility` 使用设施名称，不输出精确坐标：如 `left_onion / right_onion / left_pot / right_pot / dish / serve / none`；
- `confidence` 为 0–1；
- `evidence` 只用于人工检查，不参与控制器和评分。

输出不合法时只允许按预先写好的规则重试一次；仍失败则记为无效预测和错误，不能由程序偷偷纠正成真实答案。

## 9. LLM 调用设置

- 所有条件使用同一模型、同一版本、同一 system prompt；
- temperature 设为 0；
- 保存完整 prompt、原始响应、解析结果、模型名和调用时间；
- 按 prompt 哈希缓存，避免相同请求重复付费；
- 随机抽取 10% 的固定事件重复调用三次，报告输出一致率；
- impression 之外的文本顺序和格式完全相同。

## 10. Bob 如何配合

LLM 只负责给出判断，统一控制器使用该判断：

- 推测 Alice 正在处理原料/锅：Bob 优先处理盘子、取汤、上菜；
- 推测 Alice 正在处理盘子/汤/上菜：Bob 优先处理原料、填锅、开火；
- 推测 `PRE/HOLD`：Bob 推进最紧急的未完成任务；
- 设施预测只用于避免争抢同一设施；
- 只有检测到真实的下一步路线冲突时才让路，不因为“可能同路”长期等待；
- 配合规则、超时、退让和寻路在所有条件完全一致。

在正式调用 LLM 前，控制器必须通过三个门槛：

1. 给它 Alice 的 oracle 意图/设施时，pre 与 post Alice 都能稳定完成任务；
2. oracle 预测的得分明显高于随机预测，证明预测会影响合作；
3. 使用正确设施预测后，争抢设施或堵塞次数低于不使用设施预测，且不能靠大量停留换取“少碰撞”。

任何一项不满足，先修改控制器，不消耗 LLM 调用额度。

## 11. 正式实验条件

相同地图、horizon、起点和配对 seed 下运行：

1. `pre Alice + correct pre impression`：基础组；
2. `post Alice + stale pre impression`：核心实验组；
3. `post Alice + updated post impression`：核心对照组；
4. `post Alice + no impression`：判断印象是否真的有价值；
5. `post Alice + oracle intent/facility`：仅作合作上限，不参与 motivation 的主要比较。

核心比较仍为第 2 与第 3 组。

## 12. 两部分评估

### A. 固定事件反事实

从独立测试轨迹中预先抽取相同事件，分别提供旧、新、无印象。先检查：仅切换 impression 是否真的改变 LLM 对同一个动作的理解。

为控制费用，先使用按意图和难度分层抽样的固定事件集。若新印象在模糊事件上没有优于旧印象，停止，不进入昂贵的在线阶段。

### B. 在线合作

LLM 的预测真正驱动 Bob 行动，同时记录准确率与团队总分。在线轨迹会分叉，因此在线准确率只描述实际经历；因果判断以固定事件反事实为主，团队效果以同 seed 配对得分为主。

## 13. 指标与通过标准

用户指定的两个核心指标：

- Bob 意图预测准确率；
- 团队总得分，同时报告送汤数。

辅助指标：

- 目标设施准确率；
- 意图与设施同时正确率；
- 模糊事件准确率；
- 有效观察覆盖率；
- JSON 无效输出率；
- 重复调用一致率；
- 抢同一设施次数、真实路线冲突次数、停留和让路次数。

只有同时满足下面两项，才将结果视为支持 motivation：

1. 在完全相同的固定模糊事件上，新印象的意图准确率高于旧印象；
2. 在线相同 seed 下，新印象组团队得分高于旧印象组。

如果只提高预测但不提高得分，只能说明印象影响理解，不能说明改善合作；如果只提高在线得分而固定事件预测不变，不能把差异归因于印象。

## 14. 分阶段停止规则

```text
地图歧义检查不通过 → 改地图
Alice-post 没有稳定强于 Alice-pre → 重做 Alice 训练
oracle 控制器不优于随机控制器 → 改 Bob 控制器
固定事件中新印象不优于旧印象 → 报告负结果，暂停在线 LLM 实验
以上均通过 → 开展在线四条件实验
```

这些门槛在看到正式结果前固定，避免为了得到预期结论不断调整实验。
