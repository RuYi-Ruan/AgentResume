# M16-V2 实验方案：动作相似时，旧印象是否会让 Bob 误解成长后的 Alice

> 状态：已于 2026-09-11 通过用户审核。按门槛依次实施；固定事件门槛通过前不调用 Qwen。

## 1. 这次到底要验证什么

Alice 经过训练后，从较保守的做法变成会提前准备下一锅。Bob 只能看见 Alice 的外在行为，不能读取她的内部目标。

我们要验证的是：

```text
Alice 最初做出了一个可以有多种解释的动作
                ↓
Bob 使用过去形成的旧印象，仍按“保守的 Alice”理解她
                ↓
Bob 猜错 Alice 现在的意图，做出重复劳动或错误避让
                ↓
团队得分下降

如果 Bob 使用成长后的新印象，则应当更容易猜对并改善配合。
```

这里的重点不是证明 Qwen 会不会看方向，而是检查：当眼前动作不足以确定答案时，对伙伴的印象是否会影响理解和合作。

## 2. 上一版为什么不能直接继续

上一版 Alice 的可见行为几乎直接暴露了答案：

- 原地不动通常就是 `HOLD`；
- 空手移动通常就是 `FETCH`；
- 手持洋葱移动通常就是 `PLACE`。

Bob 即使完全没有印象，也可能只凭“有没有移动、手里拿着什么”答对。因此上一版训练得到的 Alice checkpoint 只用作设计过程记录，不进入新实验的正式结果。

## 3. 新版最关键的改动：同路但不同目的

我们只在下面这种关键局面研究印象：

- 一口锅正在烹饪；
- 另一口锅仍能继续放洋葱；
- Alice 当前空手；
- Alice 开始向一段共用通道移动。

成长前后的 Alice 在开始阶段做出相同或非常相似的移动，但目的不同：

| Alice | 实际意图 | 后续目标 |
|---|---|---|
| 成长前 Alice | `PRE`：关注当前正在烹饪的锅 | 前往锅附近的非阻塞等待区 |
| 成长后 Alice | `FETCH`：提前准备下一锅 | 前往洋葱台 |

地图需要让上述两个目标共享至少一段初始路线。Bob 在看见第一个关键移动时不能只靠方向排除其中一个答案。

`PRE` 不是模糊的心理标签。它有可以检查的外在定义：Alice 前往指定的安全等待区，之后关注当前锅，而不是去拿新原料。等待区不能占用锅口、设施交互位或主通道。

## 4. Bob 什么时候猜

Bob 不需要每一步都猜，只在预先定义的关键决策段猜一次：

1. Alice 开始一个新的宏观任务；
2. Alice 执行动作前位于 Bob 的 3×3 视野内；
3. Bob 亲眼看见该段中的第一个新动作；
4. 此时该动作同时与 `PRE` 和 `FETCH` 相容；
5. Bob 立即预测，不能继续观看后续动作再作答。

同一段任务后续即使连续走很多步也不再猜。Alice 不在视野内时，不通知 Bob、不补播动作，也不计入准确率。

动作是否“有歧义”由实验前写好的地图与路径规则判断，不能因为 Qwen 某次答错了才把它临时算作困难事件。

## 5. Bob 能看到什么

Bob 可以使用：

- 以自己为中心的 3×3 当前视野；
- 视野内 Alice 的位置、手持物和刚刚执行的真实动作；
- 自己的手持物、剩余时间和当前得分；
- 自己过去亲眼看见并保存下来的厨房设施信息；
- 厨房地图结构，因为合作双方本来就知道地图；
- 自己和当前可见 Alice 的公开地图坐标，用于正确理解局部画面的方位；
- 指定版本的 Alice 印象。

Bob 不能使用：

- Alice 的 `PRE/FETCH` 正确标签；
- Alice 的目标设施或规划路径；
- Alice 的 checkpoint 名称、训练轮数、能力等级；
- Bob 视野外的实时厨房状态和 Alice 动作；
- 未来动作。

程序可以读取隐藏标签用于事后评分，但不会把它放进 Qwen 的输入。

## 6. Alice 的旧印象和新印象如何产生

印象来自与正式测试 seed 完全分开的历史合作局。历史 Bob 与正式 Bob 使用相同的视野规则，只记录当时真正看见的行为。

- 旧印象：只根据成长前 Alice 的历史可见行为整理；
- 新印象：只根据成长后 Alice 的历史可见行为整理；
- 无印象：只说明 Alice 是合作伙伴，不描述个人习惯。

旧、新印象使用同一模板、相同字段和接近的长度。内容只陈述可观察习惯，例如“当一口锅正在烹饪时，Alice 后来出现在锅附近或原料区域的可见频率”。不写入内部意图标签，也不直接说“她已经成长”“她更强”或告诉 Bob 当前局面的正确答案。

印象先由程序按照固定统计口径生成，再转成固定模板文本，不让另一个 LLM 自由发挥总结，以免偷偷带入额外信息。

## 7. Qwen Bob 的工作

固定使用项目已有的 `Qwen/Qwen3.5-9B`。Qwen 只负责理解 Alice，不直接生成移动按键。输出格式固定为：

```json
{
  "intent": "PRE 或 FETCH",
  "facility": "设施名称或等待区名称",
  "confidence": 0.0,
  "evidence": "仅引用当前可见动作和印象"
}
```

主指标只看 `intent`。设施预测用于辅助 Bob 避免抢同一个设施或堵路，不要求精确坐标。

所有实验条件使用相同模型、提示词、温度和输出格式，唯一变化是印象文本。无效 JSON 最多按固定提示重试一次，仍失败就记为错误，不能由程序偷偷修正成正确答案。

提示词同时要求模型承认关键第一步具有歧义、不得把移动方向单独当作答案，并且不得声称当前看不见的具名设施就是 Alice 的目标。程序另行统计证据越界率；提示词服从本身不能替代这一检查。

## 8. 猜测如何影响合作

所有条件共用同一个 Bob 执行控制器：

- 如果 Bob 判断 Alice 在 `PRE`、准备关注当前锅，Bob 就优先去取洋葱并推进下一锅；
- 如果 Bob 判断 Alice 在 `FETCH`、准备处理下一锅，Bob 就优先处理盘子、取汤或上菜；
- 设施预测只用于选择替代设施和避免短期路线冲突；
- Bob 不会因为不确定就长期站着不动；
- 预测只触发一次完整但有限的任务承诺：补完一个洋葱，或完成一次拿盘—取汤—上菜；任务完成后 Bob 回到常规职责。

这样，猜错会自然造成重复取料、遗漏上菜或路线争抢；猜对则能改善分工。控制器规则在看到正式结果前冻结，所有印象条件完全相同。

## 9. 实验分成两部分

### A. 受控的同动作判断

先构造一批合法厨房局面，让成长前和成长后 Alice 从完全相同的公开状态出发。只保留两者第一个可见动作相同、但实际意图分别为 `PRE` 和 `FETCH` 的配对事件。

对每个事件只切换印象，比较：

1. 正确印象；
2. 错位印象；
3. 无印象。

事件集中 `PRE/FETCH` 数量保持平衡。这样不能靠永远回答 `FETCH` 获得高准确率，也能直接检查同一个动作是否会因印象不同而被解释成不同意图。

如果在这一步中新印象并不比旧印象更准确，实验如实记录负结果，并暂停昂贵的在线阶段。

### B. 真实在线合作

让冻结的成长后 Alice 与 Bob 完整合作。使用相同的随机起点和 seed 比较：

1. 成长后 Alice + 旧印象 Bob；
2. 成长后 Alice + 新印象 Bob；
3. 成长后 Alice + 无印象 Bob；
4. 成长后 Alice + 正确意图 Bob，作为合作上限，不调用 Qwen。

另跑“成长前 Alice + 旧印象 Bob”作为背景基线，但核心比较始终是成长后 Alice 的旧印象组与新印象组。

在线轨迹会因为 Bob 的选择逐渐分开，所以准确率因果判断主要依靠 A 部分的相同事件；B 部分主要回答配合和得分是否改善。

## 10. 正式指标

用户指定的两个核心指标：

- Bob 的意图预测准确率；
- 团队总得分，同时换算成成功上菜数量。

准确率主要报告预先定义的 `PRE/FETCH` 关键歧义事件。其他容易判断的事件如果保留，只单独作为补充结果，不能混进来稀释核心问题。

辅助记录包括设施预测准确率、有效可见事件数量、重复劳动、设施争抢、真实路线冲突、停留次数和无效输出率。

## 11. 在花费 Qwen 调用前必须通过的门槛

### 门槛 1：Alice 确实成长

在至少 16 个未参与训练和选模的 seed 上：

- 成长后 Alice 平均至少比成长前多上 4 份菜；
- 至少 12/16 个 seed 成长后得分更高；
- 两者均不能靠大量卡死或零分形成虚假差异。

### 门槛 2：真实动作确实有歧义

- 能收集至少 40 对严格匹配事件，共 80 条事件记录，`PRE/FETCH` 各 40 条；
- 每对事件公开状态一致，第一个可见动作一致；
- 去掉 impression 后的简单基线不能仅凭手持物或动作轻松达到高准确率；
- 正式测试事件不能来自训练 seed 或印象生成 seed。

如果无法自然获得足够事件，先修改地图或等待区，不能降低标准后硬跑 LLM。

### 门槛 3：猜对确实有助于合作

在不调用 Qwen 的情况下比较正确意图控制器和错误/随机意图控制器：

- 正确意图控制器的平均得分必须更高；
- 改善不能主要来自 Bob 长时间停留；
- 正确设施信息应当减少重复劳动或冲突。

如果控制器对猜测不敏感，先修控制器，否则再准的预测也无法验证“更好地配合”。

## 12. 运行顺序与停止规则

```text
调整地图和 PRE 等待行为
        ↓
重新训练 Alice-pre / Alice-post
        ↓
检查能力提升门槛
        ↓
生成并检查 PRE/FETCH 配对事件
        ↓
验证 Bob 控制器确实会利用预测改善合作
        ↓
小规模 Qwen 固定事件试跑
        ↓
固定事件通过后，才运行正式在线合作
```

任何一道门槛失败，都保存结果、说明原因并停在该阶段，不继续消耗 API 调用。

## 13. 如何判断 motivation 得到支持

只有同时出现以下两项，才说结果支持当前 motivation：

1. 对完全相同的关键歧义事件，新印象比旧印象带来更高的意图准确率；
2. 在相同起点 seed 的在线合作中，新印象组的团队总得分高于旧印象组。

如果只提高准确率但没有提高得分，只能说印象影响了 Bob 的理解，不能说改善了合作。如果得分提高但固定事件准确率没有提高，也不能把得分差异归因于印象更新。

## 14. 本轮需要用户审核的决定

1. **成长前行为**：接受成长前 Alice 主动走到锅附近安全区等待（`PRE`），而不是原地 `HOLD`。
2. **核心歧义**：正式主分析集中在 `PRE` 与 `FETCH`，其他意图只作为补充。
3. **观察时点**：Bob 看见关键段的第一个动作后立刻猜，不允许等后续动作暴露答案。
4. **印象来源**：印象只能由历史 Bob 真正看到的行为统计生成，不使用 Alice 隐藏标签和训练信息。
5. **Bob 的职责**：Qwen 负责猜意图和设施，统一控制器负责行动；第一阶段不让 Qwen 直接控制每一步。
6. **能力门槛**：16 个独立 seed，成长后平均至少多 4 份，并在至少 12 个 seed 上更好。
7. **事件门槛**：至少 40 对严格匹配事件，共 80 条事件记录，`PRE/FETCH` 各半；不足就继续改地图，不直接跑 Qwen。
8. **正式条件**：核心比较为成长后 Alice + 旧印象、新印象、无印象；oracle 只作为上限。
9. **结论标准**：准确率和团队得分必须同时改善，才能完整支持 motivation。
