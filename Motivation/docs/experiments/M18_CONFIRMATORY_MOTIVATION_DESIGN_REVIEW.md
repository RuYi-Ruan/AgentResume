> 2026-09-15 更新：用户已确认 `3 Alice seeds × 3 maps × 50`，并从开始覆盖全部意图。当前已确定规模和预测范围，正在细化执行配置；本文其余新增细节仍为设计建议，尚无 M18 实验结果。

## 1. 为什么需要 M18

M17 已在一对成长前/后 Alice checkpoint、一张地图和 80 个严格配对局面中，观察到旧印象明显降低意图准确率，并降低关键局面续局得分。它是有力的**机制性 pilot**，但当前结论不能自然外推到不同训练过程、不同地图或随机起点完整合作局。

关键限制不是简单的 `N=80`：

1. 80 个局面全来自同一对 Alice 与同一地图；不同 event ID 不等于 80 次独立成长实验。
2. 事件由受控状态枚举产生，`seed=0`、相同 `episode_id` 不是 80 局自然对局的来源标记。因此附件建议的“按来源 episode/seed 划分”应应用于自然轨迹；受控局面则必须按状态族/生成批次分组，不能仅检查 event ID。
3. 当前筛选固定为 `pre=PRE、post=FETCH` 且第一步相同；+52.5 个百分点是**该类歧义局面下**的条件效应，不是所有决策的平均损失。
4. 随机起点 8 局中，1071 次 Alice 新决策只有 1 次 Bob 恰好看见，当前地图无法支撑自然完整协作的印象干预。
5. 700 步完整局常接近 18 份汤的上限，仅看最终上菜数容易出现得分并列；需要更敏感、提前冻结的效率指标。
6. `temperature=0` 不代表 Qwen 完全确定；开发重复输入只有 83.33% 的组三次答案完全一致。

## 2. 实验要回答的两个问题

| 实验 | 核心问题 | 独立性与结论范围 |
|---|---|---|
| A：严格配对机制复现 | 当前动作本身仍有歧义时，旧/新印象是否改变 Bob 对**同一动作**的意图解释？ | 结论只针对预定义的可见歧义局面；以训练实例×地图报告复现 |
| B：随机起点自然协作 | 不人为挑选 `PRE/FETCH` 局面时，不同印象是否改变团队效率和协作冲突？ | 结论针对冻结地图、起点分布和观察规则下的完整局 |

M17 的关键局面续局分数仍作为 A 的下游控制器检查，不充当 B 的完整自然对局证据。

## 3. 推荐的主设计与可行性门槛

用户已确定 **3 个固定 Alice 训练 seed × 3 张地图 × 每组 50 个正式严格配对事件**，共 9 组 `pre→post` 训练配对，目标 450 个事件。每个 seed 在每张地图上独立训练一条成长链，共 9 对 checkpoint；训练 seed 与游戏起点 seed 分开管理。三张地图建议保持 11×7、相同设施类别与输入维度，改变通道和设施摆放；具体布局在开发检查后冻结，M17 地图作为开发参考。

这里的 `450` 是**计划目标，不是现成样本**。M17 单组只找到 154 个候选，不能保证新地图/新 seed 每组都有 50 个。正式 Qwen 调用之前，逐组完成无需 Qwen 的本地可行性检查，公布每组：

- Alice 是否在固定独立测试 seed 上取得能力提升；
- 全部新决策数、可见新决策数；
- 满足严格配对条件的候选数与占比；
- 去重/按状态族分组后可用于历史、开发和正式测试的数量；
- 预测能够影响 Bob 控制器得分的开发闸门。

3 个训练 seed 与 3 张地图在正式实验前固定，不能因某组效果不明显或候选少而换 seed、换地图、只报告成功组。任一组达不到数据质量或 50 个正式事件的预设门槛，应记录失败与原因并修订可行性方案，不能在正式测试中途降门槛或挑选额外局面。450 个事件用于实验 A；历史、开发数据以及实验 B 的完整游戏局数另计。

## 4. Alice：能力成长如何复现

每张地图、每个训练 seed 均执行同一条 `规则专家示范 → 行为克隆 pre → 从 pre 继续 PPO 得到 post` 管线。地图、起点生成、训练预算、网络结构、奖励和 checkpoint 选择规则在训练前冻结。

- `pre/post` 是同一次训练链的前后 checkpoint；不能使用人工切换的状态机作为正式成长。
- 对每个 seed×地图组合，训练、checkpoint 验证、最终能力测试使用互不重叠的起点 seed。
- 只用固定验证集的团队奖励选 `post`，不能用 Bob 的印象实验或歧义候选数量选 checkpoint。
- 报告**所有**预定组合的成长幅度、逐 seed 得分与失败率；成长未通过预定门槛的组合也必须保留在实验流转记录中。
- 预定门槛：独立能力测试中 `post−pre` 的配对平均上菜数大于 0，且多于半数测试起点同向提升；测试局数与具体阈值在开始训练前固定。若门槛不能稳定通过，先解决能力操纵，不进入 Bob 实验。

用户已选择从开始覆盖全部意图。Alice 现有输出本身包含 8 类，需扩展的是 Bob 的提示词、输出校验、候选生成与协作控制器；不能仅修改提示词后沿用 M17 的二分类评分。

### 4.1 全部意图及其含义

以下标签对应 `src/ocres/trainable.py` 的 `INTENTS`；含义需与目标选择和执行代码保持一致。

| 标签 | Alice 当前想完成的事 | Bob 配合方向（待实现验证） |
|---|---|---|
| FETCH | 获取洋葱 | 避开同一取料入口，承担其他可做任务 |
| PLACE | 将手中洋葱放进锅 | 让出目标锅入口，补其他锅或准备餐具 |
| COOK_START | 启动满锅烹饪 | 避免重复启动，转去备料或取盘 |
| GET_DISH | 获取盘子 | 避开同一取盘入口，承担备料等任务 |
| PICKUP | 用盘子盛出熟汤 | 让出目标锅入口，承担其他环节 |
| DELIVER | 将汤送到出餐口 | 让出出餐路线，继续厨房任务 |
| PRE | 到目标锅附近准备或等待接汤/观察烹饪 | 根据自己手持物和可见锅况，补另一环节 |
| HOLD | 暂缓任务或移动到安全等待位置 | 根据公开厨房需求自行选择任务 |

这些是目标标签，不是“向左走”等单步动作。`PRE` 在现有代码中可能涉及空手观察或持盘等汤，需要在提示词中明确；`HOLD` 也不等于每一步静止。

Bob 输出 `intent` 和目标设施 ID，允许 `unknown` 表示证据不足；`unknown` 是弃答，不是 Alice 的第九种意图。HOLD 等无设施目标使用 `none`。设施 ID 例如“锅 A”，不要求预测精确站位；地图中已知设施列表可作为公共背景，真实目标标签不进入输入。目标未知时，控制器不能读取真值补齐。

配合规则对所有印象条件一致，以 Bob 自己的手持物、合法动作与局部观察为依据；完成在手任务优先，避让必须有超时与回退，不能无限等待。表中方向需转成确定的任务优先级，并逐意图验证。Qwen 只负责意图/设施预测，执行器按固定规则行动。

## 5. A：严格配对机制实验

### 5.1 事件生成与划分

候选构造保留 M17 的审计原则：受控世界与 Bob 的局部观察相同、两位 Alice 均在同一时刻开始宏观任务、第一步**实际完成的动作**相同、动作后公开状态相同，而内部意图不同。目标设施只作评分标签，不进入提示。

所有候选先按 `训练实例×地图×锅/任务上下文×Alice/Bob 邻近位置族×第一步方向` 建立来源组。相近状态、同一受控局面衍生的变体只能进入同一个分区。分区顺序为：历史印象、开发、正式测试；正式事件不能先全部枚举后只按 event ID 随机拆分。必须同时检查公共状态哈希和预定的近重复阈值，并报告近重复被合并的数量。

自然轨迹若用于历史或 A 的候选，其**整个来源 episode/起点 seed**必须只属于一个分区；同一 episode 的多个事件不得跨历史、开发与测试。受控状态枚举没有自然 episode，不能假装用 `seed=0` 实现 episode 隔离。

每组需冻结正式 50 个事件；同时冻结历史/开发数量和取样算法。方向、锅、位置族尽量平衡，但不能因为某个条件的 Qwen 答案不好而删事件。记录“全部候选→可见→严格配对→分区→最终样本”的漏斗，防止只报告精选子集。

全意图候选接受所有 `pre_intent != post_intent` 的变化方向，不再固定 `PRE→FETCH`。建议在完成分组隔离的测试池中，按成长后意图分层分配 50 个名额：先尽量均分给实际存在的类别，类别不足的余量按固定算法分配，固定随机 seed 抽样。需在 Qwen 调用前冻结算法，并报告原始分布、入选分布和每类数量。

“预测覆盖 8 类”不保证严格配对子集中每类都有样本。例如手持汤时，DELIVER 可能直接被公开信息确定，无法形成同动作不同意图的配对。缺类如实报告，不伪造候选；对一般可见决策另做全意图覆盖诊断。分层样本的总体准确率只代表该取样规则下的歧义事件，不能当作自然游戏中的平均准确率。

### 5.2 印象与控制条件

旧/新印象继续来自 Bob 3×3 范围内**连续可见**的前/后 Alice 历史；视野空白立即断段，不保存隐藏目标或真实意图。历史片段数量、检索 `top-k`、格式和 token 预算在正式测试前固定。

| 条件 | 用途 |
|---|---|
| 旧印象 | 主对照：成长后 Alice 面前的过时历史 |
| 新印象 | 主条件：成长后 Alice 面前的更新历史 |
| 无印象 | 检查当前动作本身能提供多少信息 |
| 其他伙伴印象 | 等长度、等格式的真实“Charlie”可见历史，检验是否只是多给文本就能变好 |
| Oracle 意图 | 控制器上限：正确意图/目标只给执行器，不给 Qwen，也不属于真实 Bob 的方法结果 |

“其他伙伴印象”需来自**另一位独立训练的伙伴**，并与当前 Alice 的印象同地图、相同样本量和检索格式。若其习惯恰好与成长后 Alice 类似，它就不是有效的“错误身份”对照，必须事先量化相似度并如实报告，不能事后挑一个特别不相似的 Charlie。`Oracle Current Profile` 只告知伙伴类型，不一定等于意图预测上限；真正的行动上限应使用 Oracle **意图**。

### 5.3 Qwen 重复性与预算

正式主比较的每个 `事件×印象条件` 调用 3 次，温度 0；按预定多数票形成**一个事件级预测**。三次请求不是三个独立事件。平票或无有效多数票按固定规则记为错误/无效，不事后人工裁决；同时报告完全一致率、有效率与单次调用结果。

按用户确定的 9 组、每组 50 个事件，若旧/新/无/其他伙伴四种 Qwen 条件都重复 3 次，实验 A 预计为 `450×4×3=5400` 次 API 调用。仅旧/新/无三种条件则为 4050 次；是否加入其他伙伴对照仍需确定。另计历史构建（如使用模型）、开发检查、格式重试与实验 B。**这是调用量估算，非费用或严格上限。**具体预算需结合实际 token 和 API 单价计算。Oracle 意图不需要 Qwen 调用。

8 类可能出现三次答案各不相同；此时记弃答并计入准确率分母，不丢弃困难事件。意图与设施分别投票，设施仅在意图一致的输出中聚合；意图有多数而设施无多数时，保留意图、设施记 unknown。报告意图准确率、逐类正确数/样本数、混淆矩阵、类别平均准确率及弃答率，设施准确率作为辅助指标。

## 6. B：随机起点自然协作实验

B 必须从预先冻结的**合法随机起点分布**启动完整 episode，不先读取 Alice 的 `PRE/FETCH` 标签挑出局面，也不把 Bob 瞬移到 Alice 身旁。旧/新/无/其他伙伴条件使用相同起点 seed 与同一套 Alice、Bob 控制器。

先在开发阶段用不依赖 Alice 内部意图的可见事实检查 Bob 的介入机会：例如局部视野内 Alice 的手持物变化、设施交互、可见路线转折。提问时刻由公开行为变化检测器决定，加入片段去重与冷却时间，避免连续移动每步重复提问。不能由隐藏 `decision_id` 给 Bob 通知；真实意图仅用于事后评分和诊断。预测覆盖 8 类并允许 unknown，行动映射采用第 4.1 节的统一控制器。公开触发时刻未必精确等于真实意图切换时刻，需报告重复触发、遗漏及延迟。

地图或 Bob 的固定支援路线可在开发阶段为可观察性修改，但必须在正式起点与结果出现**之前**冻结。开发门槛建议同时要求每局平均至少 3 次公开触发、没有单个位置族贡献超过半数触发；实际阈值及局数需审核确定。若仍近乎没有触发，应报告“当前局部观察设置下干预机会不足”，不能只跑几局最终得分便归因于印象。

建议主效率指标为**前 300 步的团队上菜数**，并保留 700 步得分、完成前 5 份汤所需时间、重复拿料/抢同一入口、堵塞次数和 Qwen 调用次数作为辅助指标。现有 700 步、18 份汤常接近上限，因此只看 700 步总分可能掩盖合作差异。`300` 是待审核建议，正式前必须固定。自然完整局的独立统计单元为**起点 episode**，多个 episode 再嵌套于训练实例×地图；不能把一个 episode 内的多次猜测当成多局合作得分。

## 7. 预先冻结的统计与报告

| 指标 | 主分析 | 必须同时报告 |
|---|---|---|
| A：成长后 Alice 的意图准确率，新−旧 | 每个严格配对事件的多数票；逐组合 McNemar 表、总体配对差 | 各训练 seed×地图组的正确数、差值、有效率；分层/按组重采样区间；全部候选的选择比例 |
| B：前 300 步团队上菜数，新−旧 | 同起点 episode 配对差；配对随机化/置换检验或精确符号检验 | ties、均值差、配对区间、逐组合结果与冲突次数 |

- 主假设只有 `Updated > Stale`；`Updated−No`、`No−Stale`、其他伙伴对照和目标设施准确率为次要比较，事先定 Holm 或其他多重比较修正。
- 组间推广不能只将 450 个事件压平得到一个极小 `p` 值。逐一展示 9 个训练实例×地图组合的方向和效应，并分别汇总训练 seed、地图与意图类别。统计区间需考虑同训练实例、地图和状态族的相关性；只有 3 张地图、每图 3 次训练，不能把单个 p 值当作广泛泛化的充分证据。
- 估计区间必须与真实重采样单元匹配。M17 的逐 event bootstrap/sign test 只描述那一对 Alice、一张地图中的 80 个局面，不是跨训练实例的误差范围。
- 若正式组合中存在能力增长失败、候选不足、不可见或 Qwen 无效，应报告全部计划组合和失败原因，不只汇总通过的组合。

## 8. 开始前要冻结什么

1. 三张地图的具体布局与设施规则；3 个训练 seed 和各组训练/验证/能力测试的起点 seed；
2. Alice 网络、训练预算、checkpoint 选择和能力增长门槛；
3. 候选局面生成范围、严格配对/近重复定义、所有划分与每组目标数量；
4. 印象历史来源、Bob 观察路线、检索算法、Qwen 提示词和输出校验；
5. Charlie/其他伙伴对照的生成原则，Oracle 具体给予什么真值；
6. B 的公开触发器、Bob 行动映射、开发可观测性门槛和正式起点数量；
7. A/B 的主指标、次指标、停止/失败规则、统计检验与多重比较方式；
8. Qwen 模型版本、API、重复次数、最大调用数和预算；
9. 脚本与 checkpoint 哈希、原始请求/响应、所有中间漏斗和逐组合结果的保存格式。
