# M15：观察动作后的意图与设施预测实验（已审核）

> 审核状态：2026-09-11 经用户确认。可以据此实现；任何改变预测时机、标签、输入或 Bob 配合规则的修改，都应先重新审核。

## 1. 要验证的问题

Alice 训练后能力提高，但 Bob 对她的印象仍停留在成长前时，Bob 是否会：

1. 误解 Alice 已经执行的动作背后的宏观意图；
2. 判断错 Alice 正在前往的具体设施；
3. 因抢任务、抢设施或堵路而降低团队得分；
4. 在印象更新后恢复预测和配合能力。

旧 M14 没有把 Alice 的实际动作作为预测输入，只能作为探索记录，不能作为该问题的最终证据。

## 2. 预测事件

一次有效事件只在 Alice 的宏观意图相对上一次发生变化时产生：

```text
current_intent != previous_intent
```

连续移动、路线重规划、相同意图下更换路径或生成新的内部 `decision_id`，均不重复计数。目标设施变化但意图不变时也不单独触发预测。

## 3. 时序与信息边界

```text
t：Alice 选择新意图和目标设施（对 Bob 隐藏）
   Alice 执行该意图的第一个 primitive action
   环境推进一步
t+1：Bob 看到动作及其结果，预测 Alice 的意图和目标设施
     Bob 从此刻开始依据预测进行配合与避让
```

Bob 的输入可以包含：

- 动作执行前的厨房公开状态；
- Alice 的位置与手持物；
- Alice 实际执行的第一个 primitive action；
- 动作执行后的公开状态或状态变化；
- 当前条件指定的 Alice impression。

Bob 不得看到 Alice 的内部意图、内部目标、未来动作或规划路线。真实意图和设施只作为监督标签及事后评分依据。

## 4. 输出标签

### 4.1 意图

沿用八类宏观意图：

- `FETCH`：拿洋葱
- `PLACE`：把洋葱放入锅
- `COOK_START`：开始烹饪
- `GET_DISH`：拿盘子
- `PICKUP`：从锅中取汤
- `DELIVER`：上菜
- `PRE`：为即将完成的汤做准备
- `HOLD`：等待或让路

### 4.2 目标设施

预测设施身份，而不是精确坐标或路线。设施词表从当前地图的静态设施生成，例如：

- `onion_0`、`onion_1`
- `pot_0`、`pot_1`
- `dish_0`
- `serve_0`
- `none`（没有明确交互设施）

坐标只在环境内部用于将 Alice 的真实 target 转成稳定的设施 ID，不作为 Bob 的输入或输出。这样不会把路径直接泄露给 Bob，但足以支持设施避让和任务分工。

## 5. Bob 的配合规则

预测结果必须影响 Bob 后续行为，否则团队得分无法反映预测质量。所有实验条件共用同一套下游规则：

- 预测 Alice 在拿/放洋葱或开火：Bob 优先拿盘、取汤、上菜；
- 预测 Alice 在拿盘、取汤或上菜：Bob 优先拿洋葱、填锅、开火；
- 预测 `PRE` 或 `HOLD`：Bob 推进当前最紧急的未完成任务；
- Bob 避免选择 Alice 的预测目标设施；
- 有多个同类设施时，Bob 优先选择另一个；
- 预计路线在狭窄区域冲突时，离自身目标更远的一方让路。

意图预测用于任务互补，设施预测用于减少抢设施和堵塞。下游控制器必须在各条件中保持完全一致。

## 6. 实验条件

在相同地图、horizon 和配对随机 seed 下比较：

1. `pre + correct-pre-impression`：成长前 Alice 与正确旧印象；
2. `post + stale-pre-impression`：成长后 Alice 与过时旧印象；
3. `post + updated-post-impression`：成长后 Alice 与更新后的新印象；
4. `post + no-impression`：成长后 Alice，不提供印象。

核心比较为条件 2 与条件 3。除 impression 外，预测器架构、Bob 控制器、起始状态和随机种子均保持一致。

## 7. 同局记录的指标

核心指标：

- 意图准确率：正确意图数 / 有效意图变化事件数；
- 团队总得分：以环境 reward 为准，同时报告送汤数。

解释性指标：

- 设施准确率；
- 意图和设施同时正确率；
- 每局有效预测事件数；
- 堵塞/互相阻挡次数；
- 抢同一设施或重复承担同一任务的次数。

准确率和团队得分在同一在线 episode 中采集。不同条件下 Bob 行为会使后续轨迹分叉，这是衡量真实合作效果所必需的；统计时按 seed 做配对比较。

## 8. 有效性检查

实现和运行前必须通过以下检查：

- 只在意图变化时计数一次，不按 tick 或 `decision_id` 重复计数；
- 预测输入中确实包含 Alice 的第一个实际动作；
- Bob 在看到动作之前不能获得该次预测结果；
- 真实意图、真实设施和未来状态没有进入输入；
- 设施标签不向模型暴露坐标或路径；
- Bob 的预测确实改变后续配合行为；
- 四个条件只改变 Alice checkpoint/impression，不偷偷改变 Bob 规则；
- 报告逐 seed 原始数据、总体结果和配对差异。

## 9. 预期证据链

```text
Alice 成长 + Bob 印象未更新
→ Bob 对动作背后意图/设施的判断变差
→ 任务重复、抢设施或堵塞增加
→ 团队得分下降

更新 Bob 的印象
→ 预测恢复
→ 配合改善
→ 团队得分恢复或提高
```

只有预测和团队得分都沿这条链发生变化，才能把结果作为当前 motivation 的主要证据。
