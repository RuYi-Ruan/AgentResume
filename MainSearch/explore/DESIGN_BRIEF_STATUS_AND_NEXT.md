# 现状汇报与下一步计划（求指导）

> 阶段目标回顾：为主实验（ETM，演化式队友模型）确认环境与训练底座是否成立。三道前提：**P1 单人效率低**（已满足）、**P2 伙伴能力随经验演化**（现已满足）、**Oracle 门槛**（告知真实队友能力是否能改变协作决策 → 环境是否值得做 ETM）。

## 一、现在的状态

### 1. 环境与门槛（三人三臂图）

- 地图 `three_arm_v2`（19×13、107 可走格、长运输链）：脚本单人在 320 步内只能出 1.14–1.20 份（P1 ✓，脚本实测 234 步完成 1 份）。
- **Oracle 门槛（脚本角色原型作伙伴）3 种子全部为正**：关键配对（伙伴全是取料型、ego 必须补服务位）+0.62 / +0.59 / **+0.97**（t=2.5–4.9），均值 **+0.73**；在"默认行为本来就对"的配对上三种子一致无增益（+0.06 / +0.12 / −0.09）→ 机制特异性三次独立确认。
- **脚本对照（不依赖学习器）**：同一种能力信息会**翻转最优角色**——伙伴 (取料,取料) 时 ego 服务 0.80 vs 取料 0.00；伙伴 (取料,服务) 时 ego 取料 0.95 vs 服务 0.20 → 补位价值 **0.75–0.80 份/局**。

### 2. 训练底座（本轮最关键的转折）

- **外部审查发现并已修复致命 bug**：`tx.update()` 返回的已是参数更新量，却又被送进 `TrainState.apply_gradients`（内部再跑一次 Adam，并用另一套 opt_state）→ 双重优化器（符号可能翻转、两套状态各自前进）。它同时解释了此前的 critic 发散、actor 一解冻即崩、锚点越训越远。
- **修复后回归（100 预热 + 20 解冻）**：预热期团队 1.31 保持；`|V|` 34→655 变为 0.6→4.7（有界）；BC 损失 0.14→252 变为 0.22→0.18；ref-KL 0→22045 变为 0→0.004；熵 0.16→0.000 变为 0.15–0.17；解冻后团队出汤 1.31→0.00 变为 1.31→1.62→1.31。
- **P2 成立（固定身份独立 actor，各 4.9M 步）**：

| 运行 | 前 5 段 | 末 5 段/末段 | 对比 BC 1.13 | 诊断 |
| --- | --- | --- | --- | --- |
| lr_actor 1e-5 | 0.91 | 1.75（末段 1.72） | +55% | BC 损失≤0.22、ref-KL≤0.011、熵 0.13–0.17、\|V\|≤15 |
| lr_actor 5e-5 | 0.91 | **1.91（末段，31/32 局有交付）** | **+69%** | 同上，全程无崩 |

- **三个固定身份自发分化出互补角色**（24 局独立评测）：agent2 交互占比 **44–46%**（服务者），agent0/1 为 9–11%（取料者）；两两策略分布 TV **0.70–0.79**（上限 1.0）。能力来自各自 optimizer 的连续更新，非切换检查点。
- 已撤回两条在 bug 下得出的结论：① "critic LR 必须 3e-5"（修复后需重测 3e-5 / 1e-4 / 2.5e-4）；② "需要 obs 归一化"（不做、不重训 BC）。

## 二、我计划的下一步（请指正/排序）

1. **在正确优化器下重新标定学习器**（1–2 天）：lr_actor 阶梯 1e-5 → 5e-5 → **1e-4**（5e-5 目前最好）；critic LR 重测 3e-5 / 1e-4 / 2.5e-4；单次跑到 10M 观察平台期；确认是否需要把 value normalization 以正确方式（只归一化 return target）加回。
2. **用"学习器自己的轨迹"重建能力阶梯**：对同一独立 actor 训练取早/中/晚检查点（自然的连续成长），测其在固定搭档条件下的团队出汤与角色指标，确认**单调性**；然后**用这些学习型伙伴重跑一遍 Oracle 门槛**（与脚本原型版对照）。此前那版阶梯来自有 bug 的 shared 训练，非单调、太弱。
3. **主实验：ETM 对照臂**（在 P2 底座上）：`无认知 / 冻结认知（过时）/ 在线认知 / Oracle` 四臂；统一协议——同一 BC 初始化、z 权重零初始化（保证 π(o,z=0)≡π_BC(o)）、**critic 输入 = [s, z_真] 且各臂一致**（避免 value aliasing）、训练预算/锚点/调度完全一致、paired seeds + 配对 Δ 与 bootstrap CI、同时报告 policy-shift（TV/JS/共同随机数切换率）。
4. 视需要的辅助：1 轮 DAgger（3–8 万条恢复样本）；若发现协作分工需要更长视界，再考虑更长 rollout（当前 128，任务 240–320 步）。
