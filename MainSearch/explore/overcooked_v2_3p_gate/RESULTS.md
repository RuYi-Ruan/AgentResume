# 三人三臂图（three_arm_v2）：自举 + 保真协议的结果与结论（2026-09-26）

本目录记录"三人 OvercookedV2 能否学起来"这条线。目标是让伙伴能力在协作中真正演化（≥3 个固定身份、低层原子动作、不能用切换检查点模拟成长），并在该图上做 Oracle 能力门槛与 ETM 对照。

## 1. 地图（`layouts/three_arm_v2.txt`）

外部指导建议"用拓扑拉开单人/三人差距"，据此设计并经静态核验：

- 19×13、107 个可走格；左臂=食材堆、中臂=锅、右臂=盘堆+交付点，底部两行连通，三点固定起点。
- 静态估计（`check_layout_3p.py`）：单人首锅 266–280 步 → 320 步内 **1.14–1.20 份**（满足"单人 ≲1.5"的 P1）。
- 脚本路线实测（`validate_three_arm_route.py`）在修正版地图上**第 234 步完成 1 次正确交付、形状奖励 17、原始奖励 20**。
- 原版 `three_arm` 的缺陷已定位并保留为失败记录：第三个起点 (14,11) 与 B 盘堆堵死通往右臂的唯一通道（路线 221 步走完仍进不去右臂）。修正版把盘堆移进右臂、底部走廊打通。

## 2. 从零 PPO 失败（诊断）

- 三人三臂图、视野半径 3、固定起点、单一菜谱 `[0,0,0]`、320 步、共享 FF MLP（256×256）+PPO，**2.99M 步：训练侧形状奖励 0.0000、正确出汤 0**。
- 短距离对照（2 人 `grounded_coord_simple` **全可见**）3M 步同样 0/0；更早 2 人视野半径 2 跑 20M 步也是 0/0。
- 原因：V2 形状奖励表**没有"取食材"项**，最早的形状事件（放锅/取盘）都要求"手里拿对东西 + 面朝对物体"的合取；随机前馈策略撞不上 → **探索链断在第一环**，不是步数问题。
- 环境与统计已验证正常：脚本路线在同一环境里 234 步得到形状 17 / 原始 20 / 1 次交付。

## 3. 演示预热（BC）——自举成功

- `generate_demos.py`：脚本专家、**6 种角色排列**（两个取料 + 一个送菜，避免 BC 学成"固定角色脚本"）、每步重规划（把队友当动态障碍、显式跟踪朝向，防止窄通道堵死）、扰动（随机起始延迟、2% 随机动作、5% 停顿）。
  - 300 局：**294/300 局有形状奖励、251/300 局至少交付 1 次、平均 0.84 份/局**；216,000 条转移。
- **关键 bug（首次失败的根因）**：第一版把「动作 t」与「观测 t+1」配对。离线指标毫无征兆（总准确率 0.989、交互召回 0.995），但闭环完全为 0。修正配对后离线 macro 0.950、交互召回 1.00。
- `train_bc_ff.py`（均衡批：50% 均匀 + 50% 关键转移）→ `evaluate_bc.py`（jit+vmap 整回合）：
  - 离线：macro 0.950（各类召回 0.87–1.00）；
  - **闭环（采样动作）：95.3% 局有形状奖励、68.8% 局至少 1 次交付、平均 1.13 份/局（单局最多 3）** → 通过"≥75% / ≥25%"门槛。
- **观测混叠诊断**（决定要不要上 GRU）：21.6 万条专家数据上，同一观测的多数动作占比 **0.9898**、条件熵 **0.037 nats**（上限 ln6=1.79）→ **前馈 MLP 足够**，无需 CNN/GRU。
- **已知伪影**：BC 的 **argmax 策略在初始观测上会陷入"停留自环"**（贪心一步不动，故 0 份/局），而同一检查点的采样策略正常（1.13 份/局）。因此**不用 raw argmax 分歧率作核心指标**，改用采样配对收益 + TV/JS 分布距离 + 共同随机数动作切换率（`policy_shift.py`）。

## 4. PPO 保真协议（防灾难性遗忘）

- 直接 BC 权重 + 纯 PPO：第 1 段（9.8 万步）1.00 份/局 → **第 2 段归零**。
- 仅加演示正则 λ(t)·L_BC（λ0=0.5、300 更新衰减）：39 万步稳定，但 49 万步后开始下滑（0.90→0.34），**未能根治**；因为该正则只约束演示状态，而 PPO 漂移发生在自己的状态分布上。
- **最终采用的配方**（`train_overcooked_ff.py` 的 `--bc-init/--bc-regularizer/--critic-warmup-updates/--lr-actor/--lr-critic/--clip-eps/--ent-coef/--ref-kl-beta/--ref-kl-decay-updates`）：
  - 阶段 A（0–0.4M 步 = 100 次更新）：**actor 冻结，只训 critic**；
  - 阶段 B：actor LR 1e-4、critic LR 2.5e-4（`optax.multi_transform` 分组）、clip 0.1、entropy 0.001；
  - 保留演示正则 λ0=1.0 / 600 更新衰减；
  - 新增 **reference-policy KL**：β·KL(π_BC ‖ π_θ) **在 PPO 当前 rollout 状态上**计算，β0=1.0 / 500 更新衰减。
- **1M 门槛结果（通过）**：BC 起点 1.13 份/局 → 冻结期 4 段稳定 1.19；释放后 6 段：0.94 / 1.22 / 1.19 / 0.88 / 0.88 / 0.91（后段均值约 1.0，无系统性下滑）。
- 3M 与 10M 的目标：先确认 ≥2 份/局且正趋势，再上 15–20M（目标 2–4 份/局）。**未达 3M 门槛前不做 Oracle Gate。**

## 5. 下一步（Oracle Gate 设计要点，待实现）

- 混合伙伴能力档位（冻结检查点，仅用于筛选阶段）+ 给观察者注入能力信息。
- **z 输入权重必须零初始化**，保证 π(o, z=0) ≡ π_BC(o)，各臂起点严格一致。
- **critic 输入 = [s_t, z_真_B, z_真_C]，所有臂完全一致**（指导修订：能力门槛阶段若 critic 看不到伙伴档位，同一个物理状态会对应多个回报目标，重新制造 value aliasing；训练期特权信息不是执行期泄漏，因为 actor 侧仍按臂区分）。
- 指标：采样配对收益（3 seeds，paired Δ + bootstrap 95% CI）；`policy_shift.py` 的 TV / JS / 共同随机数切换率（在共享参考状态分布上，参考臂 = 无认知臂）。
- 若发现状态分布不匹配（D_expert ≠ d_π）导致恢复能力不足，优先做 **1 轮 DAgger**（3–8 万条恢复样本），而不是继续加专家演示。

## 4b. CTDE 特权 critic（2026-09-26，解决"PPO 学不动"）

### 诊断

用局部视野 critic（V(o)，1470 维）时，**解释方差 EV ≈ 0**（−0.52 / −0.09 / −0.01 / +0.03 / +0.06），价值误差与收益方差同量级，而 clip 比例 0–2%、每步近似 KL ~5e-4 → **优势基本是噪声**：策略梯度退化为随机游走，叠加熵奖励后熵从 0.18 升到 0.30，锚点（reference-KL / 演示正则）一淡出就崩到 0。21 段锚定期内也没有任何上升趋势。根因：7×7 视野看不到锅内料数/火候、队友手持与朝向，V(o) 在部分可观测下学不出来。

### 实现（`train_overcooked_ff.py`）

- `--privileged-critic`：`MLPActorCriticPriv`，actor 层（Dense_0–2）与 critic 层（Dense_3–5）**完全独立**（不共享 encoder），actor 输入不变；BC 权重按"形状匹配才覆盖"逐层载入（特权 critic 第一层输入维度不同，保留新初始化）。
- **紧凑状态（35 维）**：每智能体 7 维（x/宽、y/高、朝向/4、空手/持盘/持菜/持料 四标志）×3 + 每锅 4 维（料数/3、火候/20、已煮、空闲）+ 食材类型 one-hot + 菜谱 one-hot + 进度 t/T。不用 7410 维全可见观测（静态墙与物体位置每步重复，无信息）。
- `--value-normalization`（默认开）：用 running 均值/方差（count/mean/var 随 runner state 传递）归一化奖励后再做 GAE，使价值目标量级 ≈ 1。
- 新增诊断：`explained_var`、`adv_std`、`adv_return_corr`、`reward_mean/std`、`approx_kl`、`clip_fraction`。

### 门控顺序（指导修订）

**Critic Gate（0.3–0.5M 只训 critic，看 EV/corr/价值损失）→ 1M → 3M → Oracle Gate**；3M 通过（末 5 段均值 1.4–1.5 或明显上升）后**不再等 10M**，直接用三个不同能力检查点做 Oracle Gate；若 Δ 汤 ≈ 0 就停止，不烧 10M×3 seeds。

## 6. Oracle 能力门槛（三人图，三轮）

### 第 1 轮：用"训练阶段"当能力阶梯 —— 负结果

伙伴 = 同一 CTDE 训练在 98k / 1.47M / 2.95M 步的检查点（实测团队 0.5 / 0.9 / 1.3 份每局）。两臂各 1M 步，配对评测 32 固定局面 × 3 档 = 96 局：

- Δ 团队出汤 = **−0.02 ± 0.09**（采样，配对）
- matched-state **TV = 0.114**、JS = 0.0085、共同随机数切换率 13.6%
- 三档伙伴对结果的影响 1.34 / 0.75 / 1.38（**非单调**）→ 档位本身不构成决策相关的能力差。

### 第 2 轮：角色原型（好/弱 × 取料/服务）—— 仍为负

四个原型由同一脚本规划器生成演示、只记录目标角色智能体的转移（`generate_demos.py --role`），再 BC 成伙伴策略：

| 原型 | BC 测试总准确率 | macro | 交互召回 | 采集时团队出汤/局 |
| --- | --- | --- | --- | --- |
| 取料·强 | 0.938 | 0.940 | 1.000 | 0.90 |
| 取料·弱 | 0.584 | 0.378 | 0.840 | 0.00 |
| 服务·强 | 0.916 | 0.746 | 0.976 | 0.825 |
| 服务·弱 | 0.597 | 0.256 | 0.110 | 0.05 |

门槛用配对 (强取料, 弱服务) 与 (弱取料, 强服务)，两臂各 1M 步：Δ = **+0.03 ± 0.04**、TV = **0.015** → 负。原因见下。

### 关键环境侧证据：最优 ego 角色会随伙伴**翻转**

用脚本角色（能力天然已知、无学习器因素）在 20 局/格上测"ego 选什么角色"：

| ego 角色 | 伙伴 (强取料, 强取料) | 伙伴 (强取料, 强服务) |
| --- | --- | --- |
| **服务** | **0.80**（16/20 局） | 0.20（4/20） |
| **取料** | **0.00**（0/20） | **0.95**（19/20） |

- 伙伴**全是取料型**时，必须有人服务 → ego 服务 = 0.80、ego 取料 = 0.00（**Δ = +0.80**）；
- 伙伴里**已有服务者**时，ego 应去取料 → 0.95 vs 0.20（**Δ = +0.75**）；
- 也就是说：**同样的物理厨房、同样的局面，最优动作随"队友是什么角色"翻转，且值 0.75–0.80 份/局**。这满足"决策相关的角色能力差"判据（≥0.5–0.75 份/局）。

**第 1、2 轮门槛为负是配对选择错误**：那两组配对里"取料"在两种情况下都最优（锅区周转是瓶颈），所以 z 不改变最优动作 → TV 与 Δ 都接近 0。

### 第 3 轮：使用会翻转的配对 —— **首次为正**

配对 = (强取料, 强取料)（此时 ego 必须服务）与 (强取料, 强服务)（此时 ego 应取料），两臂各 **2M 步**，z = 每个伙伴的角色 one-hot。32 固定局面 × 2 配对 = 64 局配对评测（采样动作）：

| 配对 | 无认知 | 给认知 | Δ ± 配对标准误 | t |
| --- | --- | --- | --- | --- |
| (强取料, 强取料) —— 必须服务 | 0.69 | **1.31** | **+0.62 ± 0.24** | **2.60** |
| (强取料, 强服务) —— 应取料 | 0.38 | 0.44 | +0.06 ± 0.13 | 0.47 |
| **总体** | 0.53 | **0.88** | **+0.34 ± 0.14** | **2.43** |

- 总体 **+65%** 团队出汤，配对 t = 2.43；**增益集中在"知道队友角色才能补对位"的配对**（+0.62，t=2.60）；
- 在默认行为本来就正确的配对里没有显著差异（+0.06）→ 与"能力信息只在对位必要处起作用"的机制一致；
- matched-state TV = 0.053、JS = 0.0041、共同随机数切换率 6.3%（行为分布变化适中，收益影响更大）；
- 判据对照（指导）：通过线 Δ ≥ 0.5 且配对 CI > 0 → **总体 +0.34 未达 0.5，但关键配对 +0.62 达标且显著**；强证据线 ≥ 1.0 未达。
- 注意：给认知臂在"必须服务"配对里的 **1.31 份/局已高于脚本最优补位（0.80）**，说明学习到的策略不是简单复制脚本。

**结论（环境侧）**：三人三臂图具备"决策相关的角色能力差"——同一种能力信息会翻转最优角色，补位与不补位的落差 0.75–0.80 份/局（脚本上界），学习器能捕获其中一部分（+0.62）。下一阶段按指导转入**固定身份、独立优化的三个 actor**（主实验的 P2 要求伙伴能力随时间演化）。

### 第 3 轮：3 种子复现（指导要求筛选用 3 seeds）

| seed | 关键配对 (强取料, 强取料) Δ ± 标准误 | (强取料, 强服务) Δ ± 标准误 | 总体 Δ ± 标准误 | 总体 t |
| --- | --- | --- | --- | --- |
| 0 | +0.62 ± 0.24（t=2.60） | +0.06 ± 0.13（t=0.47） | +0.34 ± 0.14 | 2.43 |
| 1 | +0.59 ± 0.24（t=2.46） | +0.12 ± 0.14（t=0.89） | +0.36 ± 0.14 | 2.54 |
| 2 | **+0.97 ± 0.20（t=4.89）** | −0.09 ± 0.11（t=−0.83） | **+0.44 ± 0.13** | **3.33** |
| **均值** | **+0.73** | +0.03 | **+0.38** | ≈2.8 |

- 三个种子在**关键配对**上一致显著为正（+0.59 / +0.62 / +0.97），均值 **+0.73**（达到"通过线 ≥0.5"且 CI > 0；强证据线 ≥1.0 由 seed 2 单独达到）；
- 在"默认行为本来就对"的配对上一致无增益（+0.06 / +0.12 / −0.09）→ 机制特异性得到三次独立确认；
- 贪心（argmax）两臂均为 0（"停留自环"伪影，见 §3），因此门槛一律以**采样动作**判定。

### 仍需注意的混淆

我们的 shared-policy PPO **不会让策略超过 BC**（见 §4b/§4c：EV 已修好、无崩溃，但 3M 内无上升趋势）。第 3 轮门槛说明这不妨碍 ego 学到"按 z 切换角色"（+0.62、t=2.60），但在解释**其他配对**的零效应时必须保留这一保留：那里可能是策略无法适应，而不一定只是"能力信息无用"。环境侧的前提另有独立证据（脚本对照表不依赖学习器）。

### 记录：训练奖励曾漏掉 shaping 项（已修）

官方 JaxMARL OvercookedV2 基线的训练奖励是 `reward + anneal_factor · shaped_reward`（系数 1→0，horizon 1.5e7）；我们此前**只用了 raw 奖励**（shaped 仅作日志）→ 取料/锅区角色在自己的奖励里没有任何局部信用。已加入 `--shaped-coeff/--shaped-anneal-updates`，本阶段固定系数 1.0（不退火），评测仍只统计 raw 团队出汤。加上该项后 3M 仍无上升趋势（首 5 段 1.09 → 末 5 段 1.08）。
