## 二、当前困惑（三个问题）

### 问题 1（最重要）：贪心策略塌缩，动作分歧率类指标还能不能用？

- BC 检查点的**贪心（argmax）策略在闭环里 100% 选择"停留"**，一局都不动 → 0 形状奖励；而同一个检查点的**采样**策略能出 1.13 份/局（采样动作分布：右 11.7% / 下 23.2% / 左 12.5% / 上 24.9% / 停留 1.0% / 交互 26.7%）。
- 直觉解释：贪心策略自己把自己锁在"停留"上（状态分布立刻偏离演示分布），采样动作则保持探索、留在演示覆盖的状态里。
- 但**我们研究的核心指标之一是"同一局面上两臂的 argmax 动作是否不同"（动作分歧率）**，若贪心塌缩，这个指标就没意义了。

请定夺做法：
- (a) 所有比较都改用**采样动作 + 固定随机种子 + 多局平均**（放弃 argmax 指标，改用动作分布的 KL / 采样动作差异率）；
- (b) 用**先验校正**修贪心（logits 减去训练集类别先验的 log 概率），或
- (c) 在 PPO 里加大 entropy 系数／加"贪心也工作"的约束，直到贪心策略不再塌缩。
你更推荐哪一个？如果需要 (b)，请说清是实现细节（先验从哪里估、是否要再跑一次 BC）。

### 问题 2：统一初始化协议的口径是否就是你现在理解的这样？

- 同一份 BC 检查点（演示预热阶段**不给任何队友能力信息**，即 z=0）→ 复制给"无认知 / 冻结认知 / Oracle"各臂 → 正式阶段才注入不同 z。
- 各臂的 PPO 超参、演示数据、λ 正则项、步数完全相同。
- 论文里表述为 "demonstration-warm-started training protocol"，不称 from-scratch PPO。
请确认这就是你要的干净协议，或指出还需要固定/报告什么（例如种子数、λ 的敏感性）。

### 问题 3：RWARE Oracle Gate 的一个读数不一致（我正在自查）

- 训练时（脚本自带评测）报告：不给能力信息臂 `eval_overall` ≈ 4.0–4.2；给能力信息臂末段 ≈ 4.45。
- 我另写的分析脚本（用**同一个** `build_eval_fn`、同一批固定局面 32 个 × 3 个伙伴档位）读出的是**每局 200+**，两臂都是，且几乎不随伙伴档位变化。
- 数值量级差约 50 倍，且"不随档位变化"明显不对（档位本身实测是 0.00 / 3.04 / 11.54 份每局的真实差异）。
