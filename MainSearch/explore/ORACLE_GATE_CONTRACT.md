  不要为此重测画像。

## 1. 画像 z（三维，按身份分别输入，不平均）

维度定义（每名伙伴、每个候选策略各算一次）——**v2 修正：必须基于环境真实命中事件**：
1. `damage_per_len` = 该身份**真实命中事件**造成的伤害总和 / 该局局长；
2. `alive_frac` = 该身份存活步数 / 该局局长；
3. `focus_share` = 该身份的命中事件中，**同一子步**内 ≥1 名其他盟友也命中同一目标的比例；无命中记 0（不产生 NaN）。

**真实命中**必须复现环境内部口径（`smax_env.py` 的 `_world_step` / `update_agent_health`，约 L678-731）：
射程 `norm(pos_i - pos_target) < unit_type_attack_ranges[type_i]`、双方存活、`i != target`、**武器冷却 `<= 0`**；
且必须在**每个环境步的子步**粒度统计（`world_steps_per_env_step` 个子步，子步内动作相同）。
**v1 的错误**：把「下达攻击指令 + 目标掉血」当命中再**平分**伤害 ⇒ 总账能对上但**分错了人**；
「账本核对」因此**不足以**支持个人归因（该认可已撤回）。
**不预设新旧差值方向**：分子与分母都会变，新旧画像的差异以实测为准（含变大、变小、不变）。
**过量伤害口径**：主口径 = 各攻击者按自己的**原始命中伤害**计入，不按目标剩余血量分摊，过量部分仍计入该攻击者。
**必备校验（位置固定）**：在 `env._world_step(...)` 返回后、**墙体死亡处理之前**逐子步比较
`clamp(pre.health - Σ原始命中伤害, 0) == post.health`（逐单位相等，post 取 `_world_step` 返回值）；
否则必须报错。**不得**用经过 `_kill_agents_touching_walls` / `_update_dead_agents` / `_push_units_away`
之后的状态做该比较（墙造成的掉血会被误判为归因错误）。
**承伤指标待核对**：旧实现的 `damage_taken` 也用了「是否有人下达攻击指令」这类筛选，是否受影响**须先核对再下结论**；
只有团队胜率 / 回报 / 训练参数可写「不受本次归因错误影响」。

- **测量口径**：标准参考队伍 + **固定测量局面**（与训练局、测试局都不重叠；见 §3）。
- **归一化**：用**校准集 = 这 12 个候选策略的画像**算 `mean/std`（std 加 `1e-8` 防零除），**冻结**；
  `z = (profile - mean) / std`。
- **placeholder 臂输入全 0**（因为已中心化 ⇒ "全零"与"固定均值"统一）。
- **z 向量** = 按身份顺序 `[1, 2, 3, 4]` 拼接，每个身份 3 维 ⇒ **12 维**；**不得**平均成团队画像。

## 2. 伙伴序列与随机流（两臂必须逐局一致）

- **禁止**假设"同一种子 ⇒ 同一伙伴序列"：两臂局长可能不同。
- 伙伴组合与重置种子必须由 **(环境槽位 slot, 该槽位的局序号 episode_index)** 确定性生成，且**与动作采样随机流分离**：
  - `partner_stage(slot, ep_index, partner_identity)`：由 `PRNGKey(hash(PARTNER_SEED, slot, ep_index, identity))` 决定该局该伙伴取 `{u50,u600,u1250}` 中哪个；
  - `env_reset_key(slot, ep_index)`：由 `PRNGKey(hash(RESET_SEED, slot, ep_index))` 决定（同样只依赖 slot 与该槽位已完成局数）；
  - 动作采样用**独立的 rng 链**（每 update 从另一个 seed 派生）。
- 因此：即使两臂某槽位局长不同，**同一 (slot, ep_index) 的伙伴组合与初始局面在两臂中完全相同**。
  必须用短测证明这一点（见 §7 检查 2）。
- **勘误 v3（时间索引）**：`env_step_key` / `partner_action_key` 必须用**持久保存的局内步数**（`ep_length`，
  跨 rollout 不归零）作为时间索引；**不得**用 rollout 内的 `step`（每次更新归零 ⇒ 两臂局长不同时同一局内位置会拿到
  不同随机数，跨 rollout 还可能重复 key）。必备测试：两臂局长不同时，同 (slot, ep_index, 局内第 n 步) 的两个 key 一致，
  且覆盖**跨 rollout 边界**的局内位置。

| 用途 | seed 集 | 说明 |

## 4. 门槛评测（主/次指标）

- 覆盖**全部 81 种伙伴阶段组合**（3^4）× **4 个新测试局面** = **324 局/臂**。
- **配对单位 = (伙伴阶段组合, 测试局面)**；两臂用**同一批 324 个 (组合, 局面)**。
- **主指标 = 平均团队回报**；**胜局数仅作辅助**。
- 不确定性：对**这 324 个配对**做 bootstrap；报告中必须写明"这是对该固定局面集的不确定性，不是对 SMAX 总体的抽样"。
- 这些局**不是训练种子的复验**，不得当作独立样本量或复验证据。
- **勘误 v3（终止步）**：评测必须**跑到真实终止**（`done["__all__"]`），**不得**用 `max_steps` 当循环上限
  （本地环境在步数递增前判断终止 ⇒ `max_steps=5` 实际需要 6 步）；并必须**检测静默截断**：
  若有局面因保护上限退出而未被终止，必须报错/标记失败，不得当作正常结果。

## 5. 画像交换检查（匹配状态，固定 GRU 隐状态）

- 在**同一批匹配状态**（同一批局面 + 同一批轨迹位置）上，比较：
  (a) 正确画像 z；(b) **同一身份的过时画像**（该伙伴**实际用 u1250 参数**，把它的画像换成同身份的 **u50** 画像，其余 3 名伙伴不变）。
  **勘误 v3（方向）**：默认必须是「**晚期参数 + 早期画像**」= stale；**不得**默认取全 u50 组合再换成 u1250（那是"错误的未来画像"）。
  测试须断言参数阶段**晚于**画像阶段，并打印实际 (身份, 参数阶段, 画像阶段)。
- **必须固定 GRU 隐状态**：两次前向用**相同的 hstate**（在交换点注入同一 hstate），否则差异无法归因。
  短测需断言两次调用的 hstate 逐叶相等。
- 输出：动作分布 TV / JS、argmax 切换率。
- **解释约束**：动作分布变化**只说明输入影响决策，不说明这种变化有益**；写进输出说明。

## 6. 最终解释约束（写进所有输出）

- 即使**画像可分、接口正常但没有收益**，也只能写"**本配置未发现收益**"，**不能**判定"伙伴信息无价值"。
- 不做因果归因；不把局面执行次数当独立样本量；`±sd(seed)` 不是置信区间、不是判据。

## 8. 崩溃与恢复的处理约定（勘误 v3；**不得采用"崩了就直接重跑"**）

- **保留失败日志**（不得覆盖或删除）；崩溃在本机 JAX/Windows 上是**记录在案的运行风险**（参数初始化编译偶发原生崩溃、
  无 traceback），要作为风险陈述，不得写成"重跑即可"。
- **已有存档时按原配置恢复**：用 `--resume <checkpoint>`（配置必须与首次一致），而不是重新起一轮。
- **`--resume` 不得重写旧的 `run.json`**：改为写**独立文件**（例如 `run_resume-<序号>.json` 或 `resumes/` 子目录），
  并记录它续自哪个 `run.json` 与哪个 checkpoint。
