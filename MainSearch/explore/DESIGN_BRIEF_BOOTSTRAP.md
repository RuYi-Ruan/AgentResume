# 技术求助：OvercookedV2 训练无法自举（exploration bootstrap），求指导

> 目标：让一个三人 Overcooked 任务**能从头学起来**，以便检验"队友能力信息是否改变协作决策"。环境机制不能改（保持 benchmark 可比性），训练侧辅助手段必须对所有对照臂一致并如实记录。
> 算力：仅 CPU。3M 环境步 ≈ 20–35 分钟；每个实验臂可负担 10–20M 步。

## 一、研究问题（为什么需要这个环境）

我们要检验一个因果前提：**"知道自己队友当前能力水平"是否会改变我的最优协作决策**。

- 若把真实队友能力直接告诉观察者（Oracle），团队收益仍不提高 → 学习型队友模型（ETM）在这个任务上不可能有价值，该环境应被排除。
- 若 Oracle 提高收益 → 第二关再验证"过时认知 vs 当前认知"是否导致不同最优动作。

## 二、环境机制（OvercookedV2，不可改规则）

- 网格厨房。对象：`W` 墙、` ` 空地、`0-9` 食材堆、`P` 锅、`B` 盘堆、`X` 交付点、`R` 菜谱指示牌、`L` 按钮菜谱牌、`A` 起点。
- **动作语义（已实测）**：6 个动作 = 右(0)/下(1)/左(2)/上(3)/停留(4)/交互(5)，是**绝对方向移动**：一步内转身+前进；若前方被挡（含对象/墙/其他智能体）则只转身不移动。因此"面朝对象"靠一次被挡的移动完成，转向不额外计费。
- 一锅 = 同种食材 3 份；满锅后**自动**煮 20 步；必须取盘子装盘后送到 `X` 才算交付。
- **形状奖励表（关键）**：放锅 `PLACEMENT_IN_POT=3`、开火 `POT_START_COOKING=5`、取菜 `DISH_PICKUP=5`、取盘 `PLATE_PICKUP=3`。**没有"取食材"奖励**。
  - 取盘奖励有门控：仅当"手上的盘数 < 非空锅数"时给分；
  - 放锅奖励仅在"该食材与当前菜谱匹配"时给分（不匹配给 0）；
  - 交付：正确 +20，错误 −20。
- 观测：局部视野半径 r → (2r+1)² 格 × 35–40 通道；我们用的策略是**共享参数前馈 MLP（256×256，无 CNN/无 RNN）**，输入展平视野。r=3 → 7×7×35 ≈ 1,715 维。全可见会到 8,645 维（太大，不可用）。
- 每局步数可设（当前 320），超时自动重置；菜谱可从候选集合采样（当前固定单一菜谱 `[0,0,0]`，即两个食材堆都是同一种料）。

## 三、已测得的事实（本机实测，非估计）

**地图（外部指导给出的"三臂式"设计，我修正后使用）**：19×13，左臂=食材、中臂=锅、右臂=盘堆+交付，底部两行连通；107 个可走格；三个固定起点。

- 静态估计（含转向计费的上界）：单人首锅 266–280 步 → 320 步内 **1.14–1.20 份**（满足"单人 ≲1.5"的 P1 目标）。
- **脚本路线验证（实测）**：手工规划路线（BFS 路径 + 撞击转身 + 交互）在 **234 步内完成 1 次正确交付**，累计形状奖励 17、原始奖励 20 ✓ 说明该图机制上可解、环境与奖励统计正常。
- **训练失败（关键）**：
  - 三人三臂图 + r=3 + 固定起点 + 单一菜谱 + 共享 FF MLP + PPO（64 环境 × 64 步、LR 2.5e-4、clip 0.2、2 epoch × 4 minibatch、3M 环境步）：**训练侧形状奖励 = 0.0000，正确出汤 0**，评测（32 固定局面 × argmax/采样）也是 0。
  - 对照（2 人 `grounded_coord_simple`，**全可见**，短距离，3M 步）：同样 **0 形状奖励 / 0 出汤**。
  - 更早（2 人，视野半径 2，20M 步，4,880 次更新）：仍然 0 形状奖励 / 0 出汤。

**结论**：从零探索的前馈策略**连第一个形状奖励事件都触发不到**。原因是奖励表没有"取食材"，而"取盘/放锅"要求"手里拿着对的东西 + 面朝对的物体 + 交互"的合取事件；在这类地图上（堆→锅 21–26 步）随机策略几乎撞不上。**这不是"跑得不够久"能解决的。**

## 四、我的约束

1. 环境规则不可改（只用上述对象与规则），以保证 benchmark 可比性。
2. 训练侧辅助（演示预热、课程、探索奖励等）必须**对"无认知 / 冻结认知 / 在线认知 / Oracle"各臂完全一致**，并在论文中写明。
3. 主实验要求伙伴**连续学习**（不能用切换 checkpoint 模拟成长）；但**筛选阶段**用不同能力的冻结 checkpoint 是允许的。
4. 算力：CPU-only；每个 3M 步约 20–35 分钟；期望每个臂 ≤20M 步。

## 五、候选自举方案（请评估/排序/补充）

- **A. 演示预热（BC → PPO）**：用我们的路线规划器对任意起点批量生成脚本专家轨迹（可含随机起点、随机菜谱），先用行为克隆初始化共享策略，再接着 PPO。优点：直接补上"取料→放锅"这一环；缺点：引入专家先验，需说明它不改变研究问题（研究的是队友建模，不是从零探索）。
- **B. 热身课程**：先在一张"食材堆紧贴锅、盘堆紧贴锅"的极小图上学出放锅/取盘/交付，再迁移到三臂图。优点：不动奖励；缺点：迁移能否成功未知。
- **C. 训练期探索奖励**：给"取到食材""靠近锅/交付点"小额奖励。优点：最简单；缺点：改动了奖励（虽然只在训练侧），审稿人可能质疑。
- **D. 更强探索**：RND/计数奖励等；实现成本最高。
- **E. 换网络/算法**：V2 论文指出小前馈架构在新环境学不动，需要加 1×1 卷积 + 循环层；但在本机 CNN+GRU 约慢 5–10 倍（20M 步 ≈ 2–5 小时/臂），且是否解决"第一环探索"仍未知。

## 六、我需要你回答的具体问题

1. **推荐哪个自举方案？** 给出可执行配方（演示数据量/来源、BC 训练细节与停止条件、如何接回 PPO、如何确保各对照臂一致、以及要报告哪些偏差）。
2. **网络是否是主因？** 我们该先用演示预热把 256×256 前馈策略跑起来（便宜、研究变量干净），还是直接升级到论文风格 CNN+GRU（贵 5–10 倍但更接近论文可学性）？如果升级，按本机算力应把预算定在多少步？
3. **布局是否要为"第一环可达"而调整**（例如把食材堆与锅靠近），还是坚持 P1（单人 ≲1.5 份）？有没有既满足 P1 又能自举的折中（例如中继台面、双锅不对称布置）？
4. **通过阈值**：演示预热后，1M / 3M 步应观察到什么（形状奖励 >0、首次出汤、每局 1–2 份、稳定上升）才算"自举成功"？若达到了，10–20M 步的曲线目标应是什么（对照该图容量：脚本单人 ≈1.2 份/320 步，理论三人 ≈3–5 份）？
5. **若演示预热仍不奏效**，应优先怀疑什么（观测/动作接口、PPO 超参、网络容量/记忆、任务本身），以及下一步最省时间的诊断实验是什么？
