# Oracle 信息价值门槛：方案设计（待审核，未开跑）

> 上一步结论：SMAX `2s3z` 上"独立身份能学起来"的探索门槛**已通过**（单种子 5.12M 步，见 `RESULTS.md`）。
> 本轮要回答的问题是：**把"当前伙伴的能力画像"给观察者，相比固定占位输入，是否改善协作？**
> 这是**信息价值**门槛：先确认伙伴信息值得利用，再开发动态 ETM。**本轮不含世界模型**，也不是五身份同时学习的主实验。

---

## 一、问题与判据

- 两臂在**完全相同**的伙伴、环境、局面、预算、种子与网络结构下训练，**唯一差别**是观察者的一个输入通道：
  - `profile` 臂：输入**当前伙伴的能力画像** `z`（归一化后）；
  - `placeholder` 臂：输入同维度的**固定占位常量**（不随伙伴变化）。
- **主判据**：在**固定测试局面集**上配对比较 `profile − placeholder` 的团队收益（局胜率 / 回报 / 局长），
  配对单位 = 同一局面（同 seed 同 episode 下标）；不确定性用对这些局面的 bootstrap，并声明
  "这是对该固定局面的不确定性，不是对 SMAX 总体的抽样"。
- **次判据（信息是否真被使用）**：在**匹配状态**上交换 `z`（正确 vs 占位/错误），测动作分布的 TV/JS 与切换率
  （沿用 Overcooked 侧 `policy_shift.py` / `evaluate_oracle_gate.py` 的口径）。
- **门槛不通过时的解释约束**：不得直接断定"能力信息无用"——也可能是**画像或接口不合适**，因此必须同时报告
  **画像可分性**（同一身份的 early/mid/late 画像两两是否可分）。只有当"画像可分 + 接口对齐 + 仍无增益"时，才谈"信息无价值"。

## 二、伙伴与 z 的来源（测量局 / 训练局 / 测试局三者分离）

- **伙伴**：4 名伙伴**冻结不学习**，从既有 run 的存档中取（候选集合 = 阶段 `{u50, u600, u1250}` × 身份索引，
  共 15 个网络）；每局开始由**固定种子流**为 4 名伙伴各抽一个阶段 ⇒ 伙伴能力组合在训练期内**变化**（使 `z` 具有信息量），
  但在两臂之间**完全一致**（同一序列）。
- **z 的定义**：每名伙伴一个 3 维画像 `[伤害造成/步, 存活步, 集火贡献]`，在**标准参考队伍**下测量（沿用已确认的口径：
  固定参考队伍 + 固定测量局面），归一化尺度用独立校准数据确定后**冻结**。
- **预计算而非在线测量**：候选伙伴只有 15 个 ⇒ 事先在**测量局面**（固定 seed 集 A，与训练局、测试局都不重叠）
  测出 15 个画像并存表，训练时查表取值（避免每局重复测量，也避免循环依赖）。
- **测试局**（固定种子集 C）与**测量局**（集 A）**严格分离**；训练局用自己的种子流（集 B）。

## 三、成本预估（按现有实测推算，待批准后先跑单臂 smoke）

| 项 | 估计 |
| --- | --- |
| 单臂（只训练观察者，4 名伙伴冻结；64 envs × 64 步） | 比五身份同时训练更便宜，预计 ~1,300–1,600 步/秒；5M 步 ≈ **1 小时** |
| 两臂 + 匹配状态行为检查 | **约 2–3 小时** |
| 画像预计算（15 个候选 × 测量局面） | 分钟级 |

## 四、明确的非目标

- 不做世界模型；
- 不做动态 ETM（在线信念更新）；
- 不做五身份同时学习的主实验（那需要另设设计）；
- 不把本门槛结果当成"信息有/无价值"的最终结论（见 §一 的解释约束）。

## 五、待确认点（请指示）

1. **观察者范围**：先做 1 个身份（例如 `ally_0/stalker`）作为观察者，还是 5 个身份轮换各训一个（成本 ×5）？
2. **z 的维度**：`[伤害造成/步, 存活步, 集火贡献]` 三维是否够？是否加入"承受伤害"或"到敌距离"？
3. **占位输入**：`placeholder` 用**全 0 常量**，还是用"校准集均值但固定不变"？（后者更严格，避免"有信息 vs 无信息"的尺度差异混淆）
4. **预算**：每臂 5M 步（≈1 小时）单种子是否合适？还是 2 种子以看稳定性的量级？
5. **伙伴阶段集合**：`{u50, u600, u1250}` 是否合适（u50 已具基本战斗能力，能拉开能力差）？
