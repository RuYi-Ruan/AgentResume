# SMAClite 候选环境：接入检查

候选：官方 SMAClite `2s3z`，五名合作智能体，属于不依赖星际争霸 II 客户端的轻量环境。该阶段没有训练、没有 ETM。

- 本机已安装并运行官方仓库提交 `0d6abbea1334011984ae4704a0ef7a33c36057d6`。
- 官方包要求 `Rtree==1.0.0`，本机 Windows 安装后缺少 `spatialindex_c-64.dll`；开发环境改装带 Windows DLL 的 `Rtree==1.4.1` 后，一步执行与完整对局均可运行。此依赖覆盖需在后续复现环境中明确记录与复测。
- `2s3z` 为五名智能体，每人可读取 80 维局部观测并选择可用离散动作。
- 10 个相同种子的局面分别用随机有效动作、全员停留动作运行，每条件 10 局：随机组平均回报 3.88，停留组 0；两组均 0/10 获胜。这只是结构检查，不是能力提升或 ETM 优势证据。

## EPyMARL QMIX 连续学习开发实验

- 使用官方 EPyMARL 提交 `cbc38c09588064eab978501d0f12c2cf58fa7fc2`、`2s3z` 五人地图、QMIX。单次从零连续训练约 20,000 环境步，无模型切换；`epsilon_anneal_time=15000` 是开发设置。此参考 QMIX 使用共享参数与智能体 ID，只证明环境可以学习，**不等同于正式实验要求的独立、定向 ETM 智能体**。
- 依赖修复：当前环境的 `setuptools==83.0.0` 缺少旧版 Sacred 需要的 `pkg_resources`，开发环境改用 `setuptools==80.9.0`。一次长跑在首次保存模型时因 Windows 不允许时间戳中的冒号而失败，失败记录保留为 Sacred run 2；在外部参考仓库 `src/run.py` 仅把模型目录时间戳改为 Windows 安全格式后，完整训练为 Sacred run 3。
- 训练 run 3 中 20 局非固定测试，约 36、5,096、10,165、15,188 步的平均回报分别为 0.49、3.43、5.88、8.06，胜率均为 0。
- 更严格复验：仅修改参考框架 `src/runners/episode_runner.py` 的**评测重置**，每局显式使用 `seed=101*100000+局号`，训练逻辑和模型不变。四个已保存模型各运行相同初始局面的 100 局；平均回报依次为 **0.45、3.43、5.88、8.07**，四组均 **0/100 获胜**。对应 Sacred runs 6–9；runs 4–5 是修正逐局配对之前的复验，不作为配对比较证据。
- 结论边界：已看到学习型原子动作队伍的**局部战斗回报逐步提升**，但尚未看到稳定获胜；尚未验证伙伴认知的必要性。不能把开发曲线解释为 ETM 已有效，也不能仅凭一个训练种子作正式统计结论。

下一道门槛：更长的从零连续训练先验证胜率是否出现提升；随后用真实训练轨迹检查队友行为变化是否需要历史证据才能识别，并测试这种认知能否改变协作决策。不要用切换 checkpoint 来模拟在线能力提升；保存点只用于事后评测。

## QMIX 10 万步训练诊断（单种子，开发实验）

- Sacred run 12，`2s3z`、seed 0，从零连续训练至 100,028 环境步，状态 `COMPLETED`，用时 43 分 10 秒；探索率在 5 万步降至 0.05。模型检查点仅保存至 80,185 步，训练结束时没有再保存最终模型。
- 在约 36、20,135、40,136、60,140、80,185 步，各评测 100 局；五次评测胜率均为 **0/100**，平均回报分别为 **0.48、10.51、11.35、10.70、12.91**。不同评测点使用了连续编号的不同随机局面，不是逐局配对比较。
- 训练局的 `battle_won_mean` 后期出现非零值，但不能替代独立评测胜率。控制台结束时打印的 `test_return_mean=9.1892` 是前五次评测均值的汇总，**不是** 10 万步最终模型的评测分数。
- 结论边界：局部战斗回报继续改善，但截至最新的 8 万步检查点仍没有评测获胜；尚不能判断 10 万步最终策略胜率，也不能归因于环境、算法或 ETM。保留此负结果，后续训练需确保终点模型保存与同一批局面的配对评测。

## QMIX 50 万步训练与未见种子评测（开发实验）

- Sacred run 14，seed 0，从零连续训练至 **500,041 环境步**，状态 `COMPLETED`，终点模型已保存。每约 5 万步在相同 100 个随机种子上评测：至 250,167 步均为 **0/100 胜**；从 300,171 步至 500,041 步的五个检查点均为 **100/100 胜**。这是单种子、同一批评测局面的开发曲线，表现为明显跃迁，不等于伙伴能力始终平滑提升。
- Sacred run 15：只加载 500,041 步模型，使用未在上述评测中使用的随机种子 `10100000` 至 `10100299` 测试 300 局，**300/300 胜**，平均回报 20.00；没有训练或参数更新，耗时 4 分 27 秒。
- 必须区分：`2s3z` 在不同随机种子下初始观测完全相同（本地两次重置已核验）；随机种子主要影响局内单位更新顺序。因此 run 15 只支持**同一固定布局下对战斗随机性的鲁棒性**，不支持新布局或新队友策略的泛化结论。基线已能稳定获胜，但 ETM 必要性仍未验证。

后续五人非共享 QMIX 单种子从零连续训练至 300,017 环境步，终点 50/50 胜，但 22、24、26、28 万步固定 50 局胜数依次为 50、0、32、0，显示明显波动。对 8 个检查点共 400 局的离线复放及局内历史预测诊断见 `qmix_ns_checkpoint_diagnostic/RESULTS.md`；局内 3 帧历史未改善伙伴下一动作预测，不可误写成 ETM 总体失败。

原始逐局结果见 `smoke_results.json`，脚本为 `smoke.py`。

EPyMARL 源码与 Sacred 日志在 `epymarl_ref/`，模型在 `qmix_dev_seed0/models/`。环境依赖覆盖 `Rtree==1.4.1` 与官方声明的 `Rtree==1.0.0` 不一致，目前仅验证本机可运行，正式复现需隔离环境并解决依赖锁定。
