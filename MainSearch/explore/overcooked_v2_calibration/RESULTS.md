# 双人 OvercookedV2 训练管线校准（探索记录，2026-09-24）

## 结论摘要

- 本机（CPU，JAX 0.4.36 / Flax 0.10.0）实测官方 CNN+GRU IPPO 管线约 **174–205 环境步/秒**；论文协调任务配方为 3000 万步，据此外推**单种子 41–74 小时**，三种子主实验、以及三人三套独立策略在本机不可负担。
- 第一个校准跑（`grounded_coord_simple` 双人，1,048,576 环境步，85 分钟）**没有形成出汤学习曲线**：固定局面冻结评测 16 个检查点全部 0 出汤；采样评测在 33–52 万步短暂出现每局 0.27–0.45 份正确汤（同时伴随错汤），59 万步后回到 0，策略退化为恒定动作。
- 这**不是**“OvercookedV2 不可学”的结论（只跑了论文预算的 3.3%，且缩比配置与论文配方不同），也**不是** ETM 结果。它说明按交接第 1 条要求的“可复现出汤学习曲线”在本机这个预算下没有建立起来。

## 目的与边界

- 只做训练管线校准：检查带局内记忆、学习型原子动作的官方实现能否在本机形成可复现的出汤曲线，并如实记录成本。
- 双人仅因为最容易对齐官方参考实现；**不作为**研究主结果，也不冒充官方双人基准。
- 参考代码 `../benchmark_suitability_smax/jaxmarl_ref/baselines/IPPO/ippo_rnn_overcooked_v2.py`，带两处本地兼容补丁：Flax 0.10 用 `nn.vmap` 包装 CNN；`train(rng, initial_runner_state=None)` + `RUN_UPDATES` 支持分段续跑（后者由上一会话加入，本次首次被实际运行）。

## 策略诊断（`diagnose_eval.py`、`eval_checkpoints.py`）

- 冻结评测用的 argmax 策略在欠训练时不可靠：新初始化网络的 argmax 直方图是 1600 步里 1596 次「左」；训练到 78.6 万步后，argmax 完全退化为单一常量动作（1600/1600 次「右」）。因此“冻结 argmax 评测全 0”不能单独当作“没学到东西”的证据，故补跑了采样评测（上表右侧两列）。
- 动作语义（`OvercookedActionsEnum`）：0 右、1 下、2 左、3 上、4 停留、5 交互。
- 参考策略校验：恒定「停留」= 1600 次停留、0 奖励；均匀随机 = 6 个动作各约 250–300 次、原始回报 -14.25/局、形状回报 0。说明评测harness确实执行动作、也计得出错误出汤。
- 形状奖励为 0 与 harness 无关：环境里盘子拾取只在「手上盘子数 < 非空锅数」时才给分（初始锅全空），放入锅只在与菜谱匹配时给分，所以随机策略拿不到形状奖励。
- 训练侧证据与采样评测一致：形状奖励均值在 52.4 万步达到 0.067/步后迅速衰减到 0.0002/步，原始回报长期在 0 附近（每段只有少量 -20 错汤）。

## 成本外推（用于判断可负担性）

- 用 `official_rollout`（64×256、minibatch 512、4 epoch）与 `official_envs`（256×32、minibatch 1024、4 epoch）两点做线性拟合：≈0.00607 秒/环境步 + 8.77e-5 秒/样本步。代入论文配方（256×256、minibatch 2048、4 epoch）≈**582 秒/更新**（每更新 65,536 步）→ 3000 万步 ≈ **74 小时/种子**。
- 即使按本机最优实测 205 环境步/秒，3000 万步也要 ≈**41 小时/种子**。
- 因此：三种子校准（论文用 10 个种子）、加上三人地图、加上三套独立策略（每步策略计算量约 ×3）都在本机不可承担。官方大配置还可能受 15 GB 内存限制（未实测 OOM，属外推风险）。

## 失败与偏离记录（不静默）

- 诊断脚本两次报错后修正：`jax.random.fold_in` 不接受批键（改为 vmap 折叠）；新初始化网络的 `params` 需用完整 variables 字典而非 `["params"]` 子字典。两次报错输出保留在会话记录中，未产生结果文件。
- `--resume-from` 只恢复参数、优化器状态与更新计数；环境、GRU 隐状态与采样 RNG 会重新开始（本次未使用续跑）。
- 与论文配方的差异：rollout 32 步（论文 256）、minibatch 512（论文 2048）、2 epoch（论文 4）、512 次更新（论文 3000 万步 ≈ 458 次）。因此本次**不是**论文配方的复现，只说明本机可负担规模下的表现。
- 形状化奖励与错误出汤惩罚同时存在：错汤 -20、对汤 +20（`negative_rewards=True`）。策略退化成不动的一个可能原因是“不动 ≈ 0 回报”是局部最优（假设，未单独验证）。

## 下一步选项（供决定）

1. **换 benchmark**：Hanabi 三人是本机目前唯一在可负担预算内出现过学习信号的多智能体任务（共享 IPPO 13.1 万步、3 种子，固定 64 局平均分 0–0.09 → 3.28–3.56/25）。代价是任务规模小、分数离散；需要另建三套独立策略与 ETM 门槛。
2. **继续 V2 但换训练形状**：`official_rollout` 形状（64×256、4 epoch、minibatch 512）约 112 步/秒，每 30 万步约 45 分钟。可先跑 100–200 万步看是否避免“退化到不动”，但仍远低于论文预算。
3. **缩小 V2 任务**（自建小三人地图、固定起点、单一菜谱）：与论文“简单布局也需要大量步数”的证据相冲突，风险高，且仍要过学习门槛。
