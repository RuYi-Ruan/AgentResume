# ETM 主实验探索交接（2026-09-24 v2，接替 v1）

v1（`HANDOFF_2026-09-24.md`）保留为历史记录；本文档描述 v1 之后完成的双人 OvercookedV2 训练管线校准，以及当前待决定的分叉。

## 研究目标与当前状态

研究概念仍是 Evolving Teammate Model（ETM）：至少三名固定身份智能体在持续协作中各自学习，并分别维护对其他伙伴的动态认知。**尚未选定并跑通正式主实验 benchmark，仍无 ETM 提高协作收益的正式证据。**

v1 定的第一步（校准训练管线）已完成，结论是负面的但信息充分：**本机 CPU 上无法负担论文配方的 OvercookedV2 训练，且在可负担规模下没有形成出汤学习曲线**。因此现在需要在「换 benchmark」与「继续 V2 但换训练形状」之间做决定。

## 本次完成的内容

1. **接管并验证代码现场**：v1 中未测试的 `train(rng, initial_runner_state=None)` + `RUN_UPDATES` 续训接口，本次首次实际运行。烟雾测试全部通过（零更新初始化、分段续跑推进 `update_step`/`env_step` 正确、评测确定且检查点往返逐元素一致、环境第 400 步自动重置）。
2. **新建校准目录** `MainSearch/explore/overcooked_v2_calibration/`：分段训练 + 固定局面冻结评测 + 检查点（`run_calibration.py`）、烟雾测试（`smoke_calibration.py`）、吞吐测量（`measure_throughput.py`）、评测诊断与逐检查点评测（`diagnose_eval.py`、`eval_checkpoints.py`）、`README.md`、`RESULTS.md`、`results/`。
3. **吞吐实测**（CPU，steady-state 不含编译）：最优 192.7 环境步/秒；校准配置 174；官方配方形状 112.7。两点线性拟合外推论文配方 ≈582 秒/更新 → **3000 万步 ≈74 小时/种子**，按最优实测也要 ≈41 小时/种子。
4. **校准跑**（`grounded_coord_simple` 双人，种子 0，512 次更新 = 1,048,576 环境步 = 2,621 局，85 分钟，16 个检查点）：
   - 固定局面冻结评测（argmax）16 个检查点全部 0 出汤、0 形状回报；
   - 但欠训练策略的 argmax 会退化为恒定动作，故补做采样评测：32.8 万–52.4 万步短暂出现每局 0.27–0.45 份正确汤（伴随错汤，原始回报 -6～-10），58.9 万步后回到 0；
   - 训练侧形状奖励均值 52.4 万步达 0.067/步后衰减到 0.0002/步，策略整体退化为近「不动」。
5. **如实记录偏离**：本次配置不是论文复现（rollout 32 vs 256、minibatch 512 vs 2048、2 vs 4 epoch），只覆盖论文预算 3.3%；诊断脚本两次报错后修正；`--resume-from` 只恢复参数/优化器/更新计数。
6. **第二轮 benchmark 检索（用户排除 Hanabi 后）**：本机搜索引擎被墙，改用 GitHub/arXiv/PyPI 直读。实测 SMAX `3m` 训练 9,219 环境步/秒、Jumanji `RobotWarehouse-v0`（4 智能体）原始环境 14,181–21,757 环境步/秒，分别比 V2 管线（205 步/秒）快约 45 倍与 70–100 倍；发现 InstaDeep Mava 有 RWARE/SMAX/LBF/MPE 的 JAX 训练系统与公开 10 种子曲线；Melting Pot 2 因 `dmlab2d` 无 Windows 轮子不可用。详见 `benchmark_screening_2026_09/RESULTS.md`。

7. **RWARE 4 智能体（Jumanji `tiny-4ag`）学习门槛通过（用户选定方向）**：Mava 本体在 Windows 全量安装失败（`pytinyrenderer` 需 MSVC 编译器），改为自建单文件 IPPO（Jumanji RWARE + JAX/Flax/optax），场景与超参对齐 Mava 的 `tiny-4ag`/`ff_ippo` 配置，自带固定局面冻结评测（argmax + 采样）与检查点。实测 **5,850 环境步/秒**；两个种子各 1,000 次更新 = 8.19M 环境步、约 23 分钟：训练侧每局配送 0.02→10.21 / 0.02→9.12，固定 32 局冻结评测（采样）0.03→9.09（单局最高 21）/ 0.00→10.22（单局最高 18），argmax 0→3.06 / 0→2.34；曲线形状一致、无平台或退化。详见 `rware_4p_gate/RESULTS.md`。

## 决定性约束

- 本机只有 CPU JAX（`benchmark_suitability_smax/.venv`，JAX 0.4.36 + Flax 0.10.0），15 GB 内存；GPU（MX450 2 GB）不参与。
- OvercookedV2 论文配方的**单种子**训练要 41–74 小时，本机不可负担（已完成校准并判负）。
- 换成 RWARE 后，8.19M 步只需 23 分钟（5,850 步/秒），2000 万步约 60 分钟 → 多子种、多配置的主实验在本机可行。

6. **可观察性判别实验（sensor_range 2）已完成，闭环门槛仍未通过且方向为负**：伙伴可见度 7.1%→17.0%（观测 66→178，策略前向 6,111→3,067 步/秒，环境本身恒约 12k），三臂各 8.19M 步：冻结评测采样配送 无认知 **4.38** / 冻结 4.03 / 在线 **3.53**；在线 − 无认知 **−0.84**。两点记录：提高可观察性把对照臂从 2.81 抬到 4.38（收益进策略而非 ETM 接口）；在线队友模型预测在学（交叉熵 1.572→1.257）却没转成协作收益。
7. **当前结论（跨两次配置）**：`online − none` 在 `sr=1` +0.53、`sr=2` −0.84，均值 ≈ 0 → 在“把预测分布拼进观测”的接口下，本机预算内没有可复现的闭环收益。三个候选环境也都不满足主实验条件（OvercookedV2 前馈学不动、官方配方 8 h/种子；SMAX 本预算 IPPO 0 胜；Melting Pot 无 Windows 轮子）。
8. **接口诊断完成（2026-09-26，`sr=2`，三臂各 8.19M 步）**：末段采样配送 无认知对照 **4.38** / 冻结 4.03 / 在线拼分布 3.53 / 只拼可见 3.44 / 拼 argmax 独热 **4.19** / 预测作辅助损失 3.81 → 六条臂**没有任何一条超过对照**（判据 ≥ +1 碗）。读出的信息：拼分布换成拼独热把损失从 −0.84 收到 −0.19（波动内）→ 接口噪声是部分原因；只拼可见伙伴无帮助；预测作辅助目标也拖累。
9. **本轮收束**（用户要求暂不开新训练）：环境侧只剩三条路——(A) 改 RWARE 任务让"伙伴动作影响结果"更强（改规则 + 重新过学习门槛，2–4 小时）；(B) 换 SMAX 并补能学的学习器（GRU/BPTT 或非共享 QMIX，4–8 小时，风险在实现与胜率跳变）；(C) 收束为分析型结论。**全部实验清单、判定与边界见 `EXPERIMENT_SUMMARY_2026-09-26.md`**。

**当前主要不确定来源**：单底座种子、单场景（`tiny-4ag`）、评测局面仅 32 局、信息门槛每对约 1,240 个可见测试步、闭环效应量接近噪声。

## 运行须知（重要）

- 必须用绝对路径解释器：`D:\omp\MainSearch\explore\benchmark_suitability_smax\.venv\Scripts\python.exe`；相对 `.venv/Scripts/python.exe` 在本机 shell 会解析到别的环境（没有 JAX）。

- 网络限制：本机 DNS 屏蔽 `raw.githubusercontent.com` 与主流搜索引擎；GitHub API、arXiv、PyPI、openreview 可用。
